## 2026-07-31

### 미리보기 줌 팝업 그랩 이동 + 보드 순서 교체 기능 추가
- **무슨 문제/요청이 있었나**: 스테이지 상단에 항상 고정돼있던 미리보기 줌 팝업이 거슬리니 온오프하거나 옮길 수 있게 해달라는 요청, 그리고 보드(페이지) 간 순서를 바꾸는 기능을 새로 추가해달라는 요청
- **확인해보니**: 팝업은 `position:sticky`로 항상 상단에 고정된 구조였고, 페이지 탭은 클릭으로 전환만 가능할 뿐 순서를 바꾸는 기능 자체가 없었음
- **어떻게 처리했나**: 팝업을 `position:fixed`로 바꾸고 손잡이(⠿) 아이콘을 드래그하면 원하는 위치로 옮기고 마지막 위치를 기억하도록 만듦(`localStorage`에 좌표 저장). 페이지 탭에 HTML5 드래그앤드롭(`draggable`, `dragstart/dragover/drop`)을 붙여 탭끼리 순서를 바꿀 수 있게 함(`reorderPages()`)
- **결과**: Playwright로 팝업 이동 후 위치 저장, 페이지 순서 교체 후 각 페이지 내용물이 올바르게 따라 이동하는지 확인 완료 후 반영

### 팝업 손잡이가 너무 작아서 드래그가 안 걸리던 문제
- **무슨 문제/요청이 있었나**: 위에서 옮길 수 있게 만든 팝업을 실제로 써보니, 그랩해도 안 움직인다며 "왜 lock했냐"는 지적. 베이지 배경(스테이지 전체)이 잠긴 것 같다고도 함
- **확인해보니**: 코드 자체는 정상 동작했지만, 드래그 가능한 영역이 손잡이 아이콘(16px 크기) 하나뿐이라 실제로 정확히 그 지점을 클릭하지 못하면 전혀 안 움직였던 것. 베이지 배경은 원래 스테이지 전체를 스크롤하는 별개 기능이라 거길 잡아도 팝업은 안 움직이는 게 정상 동작이었음
- **어떻게 처리했나**: 드래그 가능 영역을 손잡이 아이콘만이 아니라 팝업 전체(슬라이더 등 조작 요소는 제외)로 넓힘
- **결과**: Playwright로 팝업의 빈 공간·라벨 텍스트 아무 곳이나 클릭해도 정상 이동하고, 슬라이더 조작은 그대로 되는 것 확인 후 반영

### 페이지 삭제 기능 부재 + 파일 드래그로 사진 교체 기능 추가
- **무슨 문제/요청이 있었나**: 페이지(보드)를 추가만 할 수 있고 삭제하는 기능이 없어서 추가해달라는 요청. 그리고 파일 탐색기에서 사진을 셀 위로 직접 끌어다 놓으면 그 칸 사진이 바로 교체되는 기능도 추가해달라는 요청(다른 프로젝트 코드 참고해 정리한 스니펫 제공받음)
- **어떻게 처리했나**: 페이지 탭마다 × 버튼을 추가해 `deletePage()`로 삭제하되, 마지막 남은 1페이지는 삭제를 막고 사진이 있으면 확인창을 띄우도록 함(실행취소로 복구 가능). 셀의 `drop` 이벤트에서 `e.dataTransfer.files`로 파일 드래그인지 먼저 확인해, 파일이면 그 칸 사진만 바꾸고 기존 셀↔셀 순서교환 드래그 로직은 그대로 유지
- **결과**: Playwright로 페이지 3개 중 가운데 삭제 후 나머지 페이지 데이터 유지, 실제 drop 이벤트로 파일 이미지 교체 모두 정상 동작 확인 후 반영

### 캔버스가 화면 상단에 붙어 보이고 세로로 드래그가 안 되던 문제
- **무슨 문제/요청이 있었나**: 브라우저를 거의 최대화하고 줌 50%, 페이지 3개에 사진을 실제로 올린 상태에서, 베이지 배경을 세로로 드래그해도 전혀 안 움직이고 가로만 움직인다는 신고. 화면 중앙이 아니라 계속 위에 붙어 보인다고도 함
- **확인해보니**: 실제로 그 조건(1920×1080, 줌 50%, 3페이지, 사진 있음)을 그대로 재현해보니 캔버스 세로 길이가 화면 높이에 정확히 딱 맞아서 스크롤할 여백 자체가 0이었음 — 코드가 막은 게 아니라 진짜 남는 공간이 없었던 것. 여백을 아래쪽에만 줬던 것도 원인 중 하나(화면 로드 시 항상 맨 위 스크롤 위치에서 시작)
- **어떻게 처리했나**: 스테이지 위아래 여백을 대칭으로(화면 높이의 45%씩) 바꿔서 항상 세로 드래그 여지가 남도록 하고, 처음 열었을 때 스크롤 위치를 그 여백 한가운데로 자동 이동시켜 캔버스가 화면 중앙에서 시작하도록 함
- **결과**: Playwright로 동일 조건(1920×1080, 줌50%, 3페이지+사진) 재현해 세로 여백이 0에서 확보된 상태로 바뀐 것, 초기 로드 시 스크롤이 중앙으로 맞춰지는 것, 위/아래 양방향 드래그 모두 정상 동작하는 것 확인 후 반영

### 다운로드-미리보기 미묘한 차이(뱃지 밀림·스토어 정렬)의 진짜 근본 원인 해결
- **무슨 문제/요청이 있었나**: 뱃지 텍스트 위치가 미묘하게 밀리고, 오픈헤더 스토어명이 중앙정렬 안 되고 밀려 보인다는 신고. "익스포트랑 미리보기가 왜 자꾸 미묘하게 차이나냐"는 반복 지적과 함께, 페르소나처럼 이름이 길어 확대하면 뱃지가 커지기만 하고 위로 안 올라간다는 지적
- **확인해보니**: 지금까지 여러 차례(1~8차) 여유 마진으로 증상만 땜질해왔는데, 진짜 근본 원인은 따로 있었음 — 다운로드 엔진(html-to-image)이 CORS 때문에 CDN 폰트(프리텐다드·페이퍼로지)를 못 읽어서, 다운로드 시엔 화면과 다른 폴백폰트로 그려지고 있었던 것. 그래서 화면과 다운로드가 항상 미세하게 다른 폭으로 렌더됨
- **어떻게 처리했나**: 다운로드 직전 웹폰트를 CDN에서 받아 data URL로 만들어 `htmlToImage`의 `fontEmbedCSS` 옵션으로 직접 박아넣음 → 화면과 다운로드가 100% 동일한 폰트로 렌더. 이후 그동안 넣어뒀던 여유 마진들을 전부 제거하고, 배지 배치 로직도 "이름이 슬라이더 크기 그대로 옆에 들어가면 옆 유지, 안 들어가면 위로"로 정확하게 재정리. 배지 위치를 조정할 때마다 처음부터 다시 판단하도록 해서, 한 번 위로 올라간 배지가 조건이 바뀌어도 안 내려오던 부수 버그도 같이 잡음
- **결과**: 사용자 실제 데이터로 화면·다운로드 결과물을 나란히 비교 검증, 뱃지 밀림·스토어 정렬·잘림 모두 해소되고 페르소나 확대 시 배지가 정확히 위로 올라가는 것까지 확인 후 `main` 반영. 사용자가 "이제야 되네"로 확인. **CHANGELOG에 9차로 근본원인·해결법·교훈("여유 마진으로 덮기 전에 근본을 없애라") 상세 기록**
