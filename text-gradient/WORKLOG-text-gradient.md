## 2026-08-07

### 칸 체크박스를 파일명 줄로 옮기고, 빈자리에 순서 변경 손잡이(≡) 추가
- **무슨 문제/요청이 있었나**: 미리보기 칸 좌상단 체크박스가 사진을 가려서 파일명 쪽으로 옮기고, 비는 자리에 ≡ 모양 손잡이를 넣어 칸 순서를 바꾸게 해달라는 요청
- **어떻게 처리했나**: 체크박스를 파일명 왼쪽으로 이동, 좌상단에는 손잡이를 새로 붙임(`dragHandle`). 손잡이에서 시작한 드래그만 순서 변경으로 처리해서 사진 위 드래그(위치 조정)와 겹치지 않게 분리. 놓을 자리를 파란 세로선으로 표시하고, 화면 위아래 끝에서는 목록이 따라 스크롤됨
- **결과**: 여러 장을 골라둔 상태면 고른 전부가 한 덩어리로 이동하고 선택 상태도 그대로 유지됨. 1장 이동·2장 덩어리 이동 모두 순서가 정확하고, 손잡이 드래그 뒤 사진 위치값 변화가 0인 것 확인. 바뀐 순서는 저장돼서 새로고침 후에도 유지되고 ZIP 저장 번호도 그 순서를 따름

### 칸 아래 드롭다운이 한 장만 바뀌던 문제
- **무슨 문제/요청이 있었나**: 파일명 그룹(폴더 이름표)을 눌러 여러 장을 골라둔 상태에서 칸 아래 투명 드롭다운을 바꿔도 그 칸 하나만 바뀜
- **확인해보니**: 그 드롭다운이 선택 상태를 아예 보지 않고 무조건 자기 칸 하나만 넘기고 있었음 (`assignOverlay(it, ...)`에 항상 자기 자신만 전달)
- **어떻게 처리했나**: 선택 상태를 반영하는 함수를 거치게 바꿈 (`targetsForBulk` → `assignOverlayMany`)
- **결과**: 폴더 3장 선택 후 드롭다운 변경 시 3장 모두 배정되고, 선택이 없으면 예전처럼 그 칸만 바뀌는 것 확인

### 그냥 클릭했는데 크게보기가 안 열리던 문제
- **무슨 문제/요청이 있었나**: 사진을 한 번 클릭해서 크게 보려는데 계속 "끌기(위치 조정)"로 잡혀서 편집창이 안 열림
- **확인해보니**: 클릭인지 드래그인지를 아트보드 크기(1080) 기준으로 환산한 이동량으로 판단하고 있었음. 환산 배율이 9배쯤이라 화면에서 1px만 흔들려도 드래그로 인식됐고, 사람 손은 클릭할 때도 1~3px은 흔들리므로 사실상 매번 걸림
- **어떻게 처리했나**: 판정을 화면 기준 5px 문턱으로 바꾸고(`DRAG_MIN_MOVE`), 문턱을 넘는 순간 기준점을 다시 잡아 사진이 튀지 않게 함
- **결과**: 2px·4px 흔들린 클릭에서도 편집창이 열리고 사진 위치는 그대로, 60px 드래그는 예전처럼 위치만 이동하는 것 확인

### 칸 아래 드롭다운 줄에 페이지 번호 동그라미 추가
- **무슨 문제/요청이 있었나**: 드롭다운 줄을 1:9로 쪼개서 앞에 동그라미를 넣고 그 안에 페이지 번호를 보여달라는 요청 (배경색은 폴더 색)
- **어떻게 처리했나**: 번호는 폴더(상품) 안에서 몇 번째 장인지 = ZIP으로 저장될 때 붙는 번호와 같은 값으로 계산하고, 미리보기와 ZIP이 같은 함수를 쓰게 해서 둘이 어긋날 수 없게 함 (`pageSeqMap`)
- **결과**: 대표(★)가 1번, 대표를 바꾸면 번호가 즉시 다시 계산되는 것과 ZIP 저장 번호와 100% 일치하는 것 확인. 미리보기를 가장 작게 두면 1:9로는 동그라미가 11px라 숫자가 안 보여서 최소 16px로 제한

### 그리드 간격과 배경색 — 사진 경계가 안 보이는 문제
- **무슨 문제/요청이 있었나**: 칸 사이가 좁아 불편하니 20px로 넓혀달라는 요청, 그리고 그리드 뒷배경이 흰색이라 아트보드와 구분이 안 돼 눈에 안 들어온다는 지적
- **어떻게 처리했나**: 칸 간격을 10px에서 20px로 넓히고(위아래·좌우 동일), 페이지 배경과 카드 배경 색을 서로 맞바꿈 — 페이지가 흰색, 카드가 베이지
- **결과**: 흰 사진을 넣은 최악 조건에서도 아트보드 경계가 구분되는 것을 화면 캡처로 확인

### 사진 비율에 따라 끌기가 되기도 하고 안 되기도 하던 문제
- **무슨 문제/요청이 있었나**: 어떤 사진은 잘 끌리는데 어떤 사진은 잠긴 것처럼 확대만 되고 드래그가 안 됨. 사진 가로세로에 따라 다른 것 같으니 전부 똑같이 동작하게 해달라는 요청
- **확인해보니**: 끌 수 있는 양을 "사진이 아트보드보다 남는 부분"으로 계산하고 있었는데, 그 남는 양이 사진 비율마다 달랐음 — 세로로 긴 사진은 남는 게 많아 잘 끌리고, 4:5에 가까운 사진은 남는 게 0이라 아예 안 끌렸음
- **어떻게 처리했나**: 끌기 자체는 항상 되게 하고 "어디서 멈추나"만 규칙으로 정함. 미리보기 칸과 개별 편집창이 서로 다른 계산을 쓰던 것도 함수 하나로 통일 (`movePanBy`)
- **결과**: 비율이 제각각인 사진 5종으로 네 방향 모두 끌어봤을 때 전부 동일하게 움직이는 것 확인

### 끌기 방향 규칙을 원래 요청대로 되돌림 (좌우·위 잠금)
- **무슨 문제/요청이 있었나**: 위 수정에서 사방을 다 열어버렸는데, 원래 의도는 "제목 글자가 아래를 가려주니 그만큼 사진을 위로만 올린다"였고 좌우·아래는 잠겨야 한다는 지적. 사진이 10%만 남는 건 극단적이니 70%는 남게 해달라는 요청
- **어떻게 처리했나**: 방향별로 규칙을 고정 — 좌우는 여백이 안 생기는 선까지, 위쪽도 잠금, 아래쪽만 열어서 사진을 위로 올릴 수 있게 하되 아트보드를 세로로 70%는 덮게 제한(`KEEP_COVER`, 여백 최대 30%). 아트보드보다 작아진 사진은 아트보드 안에서만 자리 이동
- **결과**: 방향 규칙이 고정되면서 필요 없어진 "가장자리 잠금" 체크박스와 Shift+드래그 예외는 삭제해 조작을 하나로 정리. 사진 5종 × 네 방향 테스트에서 좌우 여백은 항상 0, 위로 끝까지 끌면 정확히 70%에서 멈추는 것 확인

### 스토어명 — 기본값 자동 채움과 후광 진하기
- **무슨 문제/요청이 있었나**: 스토어명이 대표 사진에만 나오던 오류 지적(적용한 아트보드 전부에 나와야 함), 매번 입력하지 않게 기본값이 채워져 있으면 좋겠다는 요청, 후광이 옅어 잘 안 보인다는 지적
- **확인해보니**: 대표 한 장에만 그리라는 제한이 월 리본 뱃지와 스토어명을 한꺼번에 막고 있었음. 후광은 색의 진하기(알파)가 1.0이 천장이라 값을 올려도 0.8→0.9에서 12%밖에 안 진해지는 한계가 있었음
- **어떻게 처리했나**: 월 리본 뱃지만 대표에 남기고 스토어명은 값이 있는 아트보드마다 그리게 분리. 새로 불러오는 사진은 스토어명을 "메가하우스 공식 스토어"로 미리 채우고, 기본값이 생기기 전에 저장해둔 작업물은 복원할 때 딱 한 번만 채워 넣음(그 뒤 사용자가 비운 칸은 비운 대로 유지). 후광은 흐림 정도를 6에서 12로 올리고, 같은 후광을 두 번 겹쳐 찍어 진하기를 확보(0.8 두 번)
- **결과**: 후광 진하기가 처음 대비 약 2배가 되는 것을 픽셀로 측정해 확인(평균 21.7 → 48). 스토어명은 값을 넣은 칸 전부에 표시되고, 비운 칸은 새로고침 후에도 빈 상태로 유지되는 것 확인

### 매칭 표가 화면을 너무 넓게 차지하는 문제
- **무슨 문제/요청이 있었나**: 표가 화면 폭을 따라 늘어나 마우스 이동이 불필요하게 길다는 지적, 그리고 표에 가로 스크롤이 생기는 게 거슬린다는 지적
- **확인해보니**: 가로 스크롤은 표가 넓어서가 아니라 표 안쪽 세로 스크롤바가 폭을 차지하면서 고정폭 줄이 그만큼 넘쳤던 것
- **어떻게 처리했나**: 표를 화면 폭에 반응하지 않는 고정폭으로 바꾸고 칸 폭을 사진 56 + 사진파일명 300 + 투명파일명 300 + 스토어명 200으로 확정. 표 안쪽은 세로 스크롤만 쓰도록 가로 스크롤을 막음. 입력칸이 칸 폭을 넘던 것도 수정(입력칸에는 기본 최소폭이 있어서 칸보다 커짐)
- **결과**: 화면이 2560이어도 표가 늘어나지 않고, 세로 스크롤이 있는 상태에서도 가로 스크롤이 안 생기는 것 확인. 스토어명 칸 200 안에 입력칸 187로 들어옴

### 엑셀 매칭 기능 삭제
- **무슨 문제/요청이 있었나**: 이제 쓰지 않는 "엑셀로 매칭" 방식을 통째로 지워서 도구를 가볍게 하고, 남는 "폴더로 빠르게 시작"에서 방법 A/B 표현도 떼달라는 요청
- **어떻게 처리했나**: 엑셀 패널과 관련 코드 전부 삭제 — 외부 엑셀 라이브러리(XLSX), 엑셀·사진 드롭존, 매칭 실행, 파일명 인덱스 함수들. 로그 박스는 폴더 패널 아래로 옮김. 제목은 "1. 투명 이미지 올리기" / "2. 폴더로 빠르게 시작"으로 정리
- **결과**: 사진 4장 + 투명 1개로 전체 흐름(폴더 불러오기 → 투명 배정 → 미리보기)이 정상 동작하고 자바스크립트 오류가 없는 것 확인

### 투명 제목이 가려주는 만큼 사진을 더 끌어올리게
- **무슨 문제/요청이 있었나**: 제목 글자가 사진 아래를 덮고 있으니 그 부분에 있는 피규어를 위로 끌어올리고 싶은데, "사진이 아트보드를 꽉 덮어야 한다"는 제한 때문에 못 움직였음
- **어떻게 처리했나**: 제목 그림에서 가로 전체가 거의 다 불투명한 줄이 위·아래로 몇 줄인지 직접 재서(`measureOverlaySafeBands`), 그 높이만큼은 여백이 생겨도 제목에 가려 안 보이므로 그 방향으로만 한계를 열어줌. 제목은 사용자가 올리는 이미지라 높이가 파일마다 달라서 추측하지 않고 알파값을 실제로 측정
- **결과**: 안전하게 잡으려고 "거의 다 불투명한 줄"만 세고 아트보드 높이의 40%까지만 허용. 제목을 배정하면 몇 px을 더 끌 수 있는지 로그로 안내

### 일괄 확대/축소·이동이 안 된다는 신고 (원인 파악에 세 번 헛짚음)
- **무슨 문제/요청이 있었나**: 여러 장을 골라놓고 확대/축소하거나 끌어도 반응이 없다는 신고가 반복됨
- **확인해보니**: 처음 세 번의 진단이 전부 틀렸음 — ① 휠 체크박스가 저장이 안 돼서 꺼진 것 ② 휠 한 칸 변화량이 작아 눈에 안 띈 것 ③ 여유가 3px뿐인데 "움직일 수 있다"고 판단한 것. 실제 원인은 따로 있었음 — **사진이 아트보드보다 작을 때 남는 양이 음수가 되는데, 판정을 "남는 양이 기준보다 큰가"로만 해서 드래그가 통째로 막혀 있었음**
- **어떻게 처리했나**: 판정을 절댓값으로 바꿔 남는 양이 음수든 양수든 그 폭만큼 움직이게 함. 앞선 세 건도 각각 수정(체크박스 상태 저장, 휠 한 칸 변화량 상향, 여유 판정 기준 16px). 조작이 실제로 몇 장에 적용됐는지 화면에 바로 표시하는 안내도 추가(`reportAction`) — 아무 표시가 없으면 조작이 코드에 도달조차 못 한 것이고, "1장"이라고 뜨면 선택이 안 잡힌 것이라 원인을 바로 구분할 수 있음
- **결과**: 휠 변화가 눈에 안 보인다는 문제를 별도로 해결하려고 선택 바에 일괄 확대/축소 슬라이더를 추가하고, 전체보기보다 더 작게(20%까지) 줄일 수 있게 범위를 넓힘. 실제 마우스로 폴더 선택 → 휠·드래그까지 재현해 확인

### 스토어명이 아트보드 맨 위에 붙어 있던 문제
- **무슨 문제/요청이 있었나**: 스토어명이 아트보드 위쪽 끝에 거의 붙어 있어서 위 여백을 15px 달라는 요청
- **확인해보니**: 여백을 글자 기준으로 계산했는데 로고가 글자의 2배 크기라 글자보다 위로 튀어나왔고, 게다가 로고 그림 자체에 위쪽 투명 여백이 27%쯤 있어서 눈에 보이는 간격은 6px밖에 안 됐음. 처음엔 24px이라고 잘못 보고했는데, 그건 이미 수정한 코드를 잰 것이라 잘못된 측정이었음
- **어떻게 처리했나**: 로고 그림에서 실제로 색이 시작하는 지점을 재두고(`measureLogoInkTop`), 그만큼 위로 당겨 그려서 "눈에 보이는" 여백이 15px이 되게 함

- **무슨 문제/요청이 있었나**: 다른 프로젝트의 "대표 지정(★) + 대표 외 꾸밈 제거" 코드를 공유받아 반영 요청. 인스타 캐러셀은 첫 장에만 제목이 필요하다는 맥락
- **어떻게 처리했나**: 폴더(상품)마다 대표 1장을 정하는 방식으로 적용. 칸마다 ★를 달고, "대표만 남기고 나머지 투명 제목 빼기" 버튼 추가. 핵심은 **나머지에서 투명을 지우는 게 아니라 표시만 끄는 것** — 배정한 투명파일명이 그대로 남아 있어서 잘못 눌러도 되돌릴 수 있음. 대표를 "몇 번째"로 기억하면 순서가 바뀔 때 엉뚱한 사진으로 옮겨가므로 사진 자체에 표시를 붙였음
- **결과**: 이미 정리한 폴더에서 대표를 바꾸면 예전 대표에도 제목이 남아 한 폴더에 제목이 두 개가 되는 문제를 발견해, 제목이 새 대표로 옮겨가게 수정
- 이어서 뱃지·스토어명도 대표에만 나오도록 바꾸고(예전엔 스토어명을 채운 모든 사진에 나왔음), 스토어명 글자색을 검정/흰색 중에 고르는 버튼을 추가. 흰 글자에 흰 후광이면 대비가 없어지므로 후광을 글자색 반대색으로 자동 전환

- **어떻게 처리했나**: 사진마다 최초 1회만 축소 캔버스(최대 변 480px)를 만들어 캐싱(`getThumbSourceCanvas`)하고, 그리드 썸네일은 항상 이 축소본에서만 그리는 전용 함수(`drawItemThumb`)를 분리. 썸네일에서는 뱃지 그림자를 생략(`drawBadge(ctx, it, {shadow:false})`)하고, 클릭해서 크게보기·실제 PNG 다운로드·ZIP 내보내기는 기존처럼 원본 화질+그림자 그대로 유지
- **결과**: 수정 전/후를 실제로 300장 합성 상태로 만들어 직접 측정 — 뱃지 켜진 상태에서 설정 하나 바꿔 다시 그리는 시간이 12~13초 → 0.3~0.8초로 줄어듦 (git stash로 수정 전 코드를 잠깐 복원해 같은 조건으로 대조 측정함)

### 파일명이 길면 썸네일 칸이 밀려 보이는 문제 + 초기화/추가 방법 문의
- **무슨 문제/요청이 있었나**: 사진 파일명이 길면 썸네일 아래 파일명을 다 보여주느라 칸 정렬이 밀려 보임. 또한 초기화 버튼이 있는지, 사진 폴더를 다시 선택하면 리스트가 초기화되는지, 초기화하고 싶을 때와 기존 리스트에 이어붙이고 싶을 때 각각 어떻게 하면 되는지 질문
- **어떻게 처리했나**: 썸네일 폭을 캔버스 폭에 고정하고 파일명은 CSS 말줄임표(`text-overflow: ellipsis`)로 잘리게 처리. "사진 폴더 선택"(기존 리스트 비우고 새로 시작)과 별도로 "폴더 추가"(기존 리스트 유지한 채 뒤에 이어붙이기) 버튼을 새로 추가. 완전 초기화는 기존에 있던 "새로 시작(캐시 지우기)" 버튼으로 안내
- **결과**: Playwright로 긴 파일명 잘림, 폴더 추가 시 기존+신규 합쳐지는 것, "새로 시작" 시 리셋되는 것 모두 확인

### 매칭표 입력칸 답답해 보이는 문제 + 로고·텍스트 재질이 따로 노는 문제
- **무슨 문제/요청이 있었나**: 매칭표의 스토어명 입력칸이 패딩 없이 딱 붙어 답답해 보임. 또한 실제 렌더링 결과 스크린샷을 보내며, 스토어명 텍스트엔 흰 테두리가 있는데 옆의 PW 로고(비트맵)엔 테두리가 없어서 서로 재질이 다르게 보인다는 지적. 흰 테두리를 로고에도 넣으면 정신없어 보이고, 배경에 흰 네모를 씌우는 것도 어색해서 좋은 방법을 고민해달라는 요청
- **어떻게 처리했나**: 입력칸 패딩을 `2px` → `6px 8px`로 확대. 텍스트의 딱딱한 흰 테두리(`strokeText`)를 제거하고, 텍스트·로고 둘 다에 공통으로 부드럽게 퍼지는 흰 그림자(soft glow, `shadowBlur`)를 적용해 같은 재질처럼 보이게 통일
- **결과**: 어두운 배경/밝은 배경 두 종류 테스트 사진으로 렌더링해서 채팅으로 미리 보여준 뒤 반영. main 배포 확인은 아직 사용자 쪽에서 진행 중

### text-gradient(원본 그라데이션 도구) PNG 다운로드 파일명 자동화
- **무슨 문제/요청이 있었나**: text-gradient 메인 도구에서 PNG로 저장하면 `slot1.png`, `slot2.png`처럼 슬롯 번호로만 저장돼서 여러 장 받으면 서로 구분이 안 됨. 특수문자만 제거하고 한글은 그대로 살리는 안전한 파일명 생성 스니펫을 공유받음
