# 접속 코드(비밀번호) 운영 안내

가이드 페이지는 접속 코드를 입력해야 열린다. 이 문서는 **코드를 어떻게 바꾸고
어떻게 관리하는지**만 다룬다. 동작 원리는 `gate.js`와 `build-lock.js` 위쪽 주석에
적혀 있다.

> ⚠️ **접속 코드 값을 이 파일이나 저장소 안 어디에도 적지 말 것.**
> 이 저장소는 공개돼 있어서, 적는 순간 누구나 볼 수 있게 된다.
> 코드가 사는 곳은 오직 **Vercel 대시보드의 환경변수 `GUIDE_PASSWORD`** 뿐이다.

---

## 어떻게 잠기나 (한 문단 요약)

가이드 본문은 서버 없이 파일만 올려두는 정적 페이지다. 그래서 "화면을 가려두고
비번이 맞으면 걷어내는" 방식은 소용이 없다 — 페이지 소스를 열면 가려둔 내용이
그대로 보이기 때문이다. 대신 **본문을 읽을 수 없게 변환한 상태로 올리고**, 코드가
맞을 때만 브라우저가 되돌려서 보여준다. 코드가 틀리면 되돌리기 자체가 실패한다.

**잠기지 않는 것**: `assets/` 폴더의 이미지. 주소를 정확히 아는 사람은 이미지
낱장을 볼 수 있다. 이미지까지 잠그면 첫 로딩이 크게 느려져서 일부러 뺐다.
이미지만으로는 순서·규칙·보상 같은 알맹이를 알 수 없다.

---

## 코드를 바꾸는 방법 (2개월마다)

1. **Vercel 대시보드** → 이 프로젝트 → **Settings → Environment Variables**
2. `GUIDE_PASSWORD` 의 값을 새 코드로 수정 → 저장
3. **재배포가 실제로 한 번 돌아야 한다** — 아래 주의사항을 꼭 읽을 것
4. 크리에이터에게 새 코드 안내

### ⚠️ 주의: 대시보드의 "Redeploy" 버튼만으로는 반영되지 않는다

이 프로젝트는 `vercel.json`의 `ignoreCommand` 때문에 **`creator-guide/` 폴더에
변경이 없으면 배포가 Skipped 처리된다.** 환경변수만 바꾸고 Redeploy를 누르면
아무 일도 일어나지 않는다.

그래서 코드를 바꿀 땐 **이 폴더의 파일을 한 줄이라도 고쳐서 push**해야 한다.
(같은 이유로 `ANTHROPIC_API_KEY`를 바꿀 때도 마찬가지다 — `api/chat.js` 주석 참고)

### 코드가 바뀌면 기존 사용자는?

브라우저에 저장해둔 예전 코드로 자동 입장을 시도했다가 실패하고,
**"접속 코드가 변경되었습니다. 새 코드를 입력해 주세요."** 안내와 함께 입력창이
다시 뜬다. 따로 해줄 일은 없다.

## 코드를 새로 만들 때

- **10자리**, 대문자·소문자·숫자를 각각 최소 1개씩 섞는다
- 헷갈리는 글자는 뺀다 — 숫자 `0`과 알파벳 `O`, 숫자 `1`과 소문자 `l`·대문자 `I`
  (카톡으로 코드를 보냈을 때 "영문 오예요, 숫자 영이에요?" 문의가 생기지 않게)

여유분 코드는 **저장소가 아닌 곳**(비밀번호 관리 앱, 개인 메모 등)에 보관한다.

---

## 알아둘 것

- **한 번 입력하면 그 기기에서 30일간 다시 묻지 않는다.** 기간을 바꾸려면
  `gate.js`의 `REMEMBER_DAYS` 값을 고친다.
- **저장소의 원본 파일은 잠기지 않은 상태 그대로다.** 잠그는 일은 Vercel이
  배포하는 순간에만 일어난다. 그래서 가이드 내용을 고칠 땐 지금까지와 똑같이
  `.jsx` 파일만 고치면 되고, 잠금은 신경 쓸 필요가 없다.
- **`build-standalone.js`로 만든 파일 하나짜리 배포본에는 잠금이 없다.**
  그건 메신저로 직접 전달하는 용도라 일부러 그렇게 두었다. 아무에게나 보내지 말 것.
- **`GUIDE_PASSWORD`가 없으면 배포가 실패한다.** 일부러 그렇게 만들었다 —
  조용히 넘어가면 잠기지 않은 가이드가 그대로 공개되기 때문이다.

---

## 이 방식의 한계 (알고 쓸 것)

이건 **링크가 아무한테나 퍼지는 것을 막는 잠금장치**다. 작정하고 시간을 들이는
사람까지 막지는 못한다. 코드를 받은 사람이 그 코드를 남에게 알려주면 그대로
들어갈 수 있고, 그건 어떤 방식으로도 막을 수 없다.

가이드 내용이 유출되면 곤란한 수준이 아니라 **유출 시 법적/금전적 문제가 생기는
수준**으로 관리가 필요해지면, 그땐 이 방식이 아니라 로그인 계정 기반으로 바꿔야
한다.
