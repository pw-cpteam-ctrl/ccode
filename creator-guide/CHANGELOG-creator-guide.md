## 2026-09-03 (V1.2 이벤트 보상 기준 통일·문구 정리)

### 보상 지급 기준 (정책 변경)
- 지급 기준을 오픈일 하나로 통일 — 당일 업로드 원칙, 선지급 없이 업로드 확인 후 지급
  (기술: `GUIDE.reward.tracks`·`trackCautions` 문구 교체)
- 오픈 후 7일 이내 업로드가 확인되면 10일차에 일괄 지급, 넘기면 프리오더 정산
  시점(오픈일 기준 약 40일)에 함께 지급
  (기술: `knowledge-megahouse.md`의 F-TRACK 항목 동기화)
- 이벤트 기간에 상한을 두지 않되 프리오더 기간 안에는 마무리하도록 안내
  (기술: `EVENT_GUIDE.musts`, FE-2·FE-3)

### 이벤트 안내 (문구 수정)
- 경품을 잘게 나누도록 유도하는 것처럼 읽히던 "경품은 이렇게 나눌 수 있어요" 단락 삭제
  (기술: `EVENT_GUIDE.details`에서 🎁 항목 제거)
- 당첨자 정보 전달의 "발표 후 3일 이내" 기한 표기를 없애고 "취합이 완료되면 공유"로 변경
  (기술: `EVENT_GUIDE.musts` 2번 항목)
- 경품 지급 시점 안내에 "발급 날짜는 크리에이터 보상과 같은 회차이고 기준만 다르다"를
  명시하고, 9일차가 10일차 발급의 전날이라는 이유를 붙임
  (기술: `EVENT_GUIDE.details`의 ⏱ 항목 `body`·`bullets`·`note`)
- 조건이 부정확하던 "이벤트를 더 길게 진행하시는 경우"를 "그 이후에 주신 경우"로 교체
- 중복 문장 정리 — 자유 안내, 담당자 공유, 프리오더 기간 언급을 각각 한 곳으로 모음
- 접힘 영역의 항목 순서를 바꿔, 뒤 항목을 앞에서 참조하던 흐름을 바로잡음
  (기술: 💬 공유할 내용을 📋 당첨자 정보보다 앞으로)
- 위아래 돌아가기 버튼의 문구가 같던 것을 구분 (기술: `.ev-back`을 "‹ 돌아가기"로)

### 챗봇 지식베이스 (오답 수정)
- "크리에이터님이 보상을 받으시는 시점과 같습니다"가 사실과 달라, 날짜는 같은 회차지만
  기준이 되는 행동은 다르다는 설명으로 교체 (기술: `knowledge-megahouse.md` FE-5)
- "정보를 빨리 주실수록 경품도 빨리 전달됩니다" 삭제 — 지급 회차가 둘뿐이라 성립하지 않음
  (기술: FE-4를 "오픈 후 9일차까지 주시면 10일차 발급 회차에 함께 나갑니다"로 교체)
- 길이가 다른 항목보다 눈에 띄게 길던 FE-2를 6줄에서 4줄로 축약

### 01 요약 카드 (문구 수정)
- "3분", "3가지"가 반복돼 숫자만 눈에 들어오던 문제 — 시간 표기를 빼고 제목을
  "먼저 봐두면 좋은 핵심 요약"으로 변경 (기술: `GUIDE.opener`)
- 요청 없이 들어가 있던 "유입 수는 구매 링크를 통해 들어온 고객 수를 말합니다" 줄 삭제

### 파비콘·마지막 화면 (UI)
- 브라우저 탭 아이콘 추가 — 별도 파일 없이 이모지를 그대로 사용
  (기술: `index.html`·`brand2.html`에 SVG data URI 형태 `<link rel="icon">`)
- 마지막 화면에서 아직 아무것도 고르지 않았을 때 카드가 연붉은색으로 보이도록 변경
  (기술: `.done-card.is-todo`)

## 2026-08-31 (V1.1 FAQ 버튼·질문 수집·접속 코드 잠금)

### 고정 질문 버튼 (신규 기능)
- 브랜드별 자주 묻는 질문 5개를 눌러서 바로 답이 나오는 버튼으로 제공 (AI 호출 없음)
  (기술: `CHAT_FAQ` 테이블, `sendPreset()`, 브랜드 키로 megahouse/brand2 분기)
- 답변 끝에 어느 탭을 보면 되는지 출처 표시, 클릭 시 해당 탭으로 이동
  (기술: 기존 출처 버튼 로직 재사용, `출처: NN 탭` 포맷 유지)

### 문의 로그 수집 (신규 기능)
- 크리에이터가 어떤 질문을 하는지, 챗봇이 못 답한 질문이 뭔지 서버에 기록
  (기술: `api/log-question.js`, GitHub Contents API로 append, 실패해도 챗봇 동작에
  영향 없도록 항상 200 응답)
- 이메일·전화번호·계정·긴 숫자열은 저장 전 자동으로 가림
  (기술: `scrub()` 정규식 마스킹, `MAX_LEN`으로 길이 제한)
- 로그 파일이 가이드 폴더 안에 있으면 문의 한 건마다 재배포되는 문제를 피하려고
  별도 폴더에 분리 저장
  (기술: `creator-logs/questions-YYYY-MM.jsonl`, `vercel.json`의 `ignoreCommand`
  범위 밖)

### 접속 코드 잠금 (신규 기능)
- 접속 코드를 입력해야 가이드 본문을 열 수 있도록 변경 — 소스를 열어봐도 본문이
  보이지 않음
  (기술: `gate.js` + `build-lock.js`, PBKDF2(20만회)+AES-GCM으로 배포 시점에 암호화,
  코드는 브라우저 안에서만 검증하고 서버로 전송하지 않음)
- 한 번 입력하면 30일간 재입력 없이 유지, 코드가 바뀌면 자동으로 재입력 요청
  (기술: `localStorage` 기반 만료 시각 저장, 복호화 실패 시 안내 후 재입력 유도)
- 코드를 모르는 방문자에게 React·Babel(약 3MB) 라이브러리를 내려주지 않음
  (기술: 잠금 해제 성공 후에만 CDN 스크립트 동적 로드)
- 코드 미등록 상태로는 배포 자체가 실패하도록 만들어 잠기지 않은 가이드가 실수로
  공개되는 걸 방지
  (기술: `GUIDE_PASSWORD` 환경변수 부재 시 `build-lock.js`가 종료 코드 1로 중단)

### 배포 설정 정리
- 도메인을 유료로 구매하지 않고 무료 주소로 변경
  (기술: `ccode-mvhy.vercel.app` → `pw-creator-guide.vercel.app`)
- 환경변수 등록만으로는 반영 안 되던 배포 문제 해결
  (기술: `ignoreCommand`로 폴더 변경 없을 시 배포가 Skipped 처리되는 것을 실제
  파일 변경으로 강제 트리거)
- 빌드 명령 추가로 발생한 배포 실패 해결
  (기술: `outputDirectory: "."` 명시 — `build-lock.js`가 파일을 제자리에서 잠그므로
  별도 `public` 폴더가 생기지 않는 구조)

## 2026-08-07 (V1.0 프로젝트 이관 및 챗봇 설계)

### 프로젝트 이관
- 크리에이터 협업 가이드 2종(메가하우스 / 굿스마일·부시로드)을 저장소로 옮김
  (기술: `creator-guide/` 폴더 신설, 브랜드별 데이터·렌더링·스타일 파일 분리 유지)
- 두 브랜드 가이드가 서로 영향을 주지 않도록 파일 분리 구조 그대로 보존
  (기술: `shared.jsx`/`shared-brand2.jsx`, `finalOption*.jsx`, `styles*.css` 각각 독립)

### 챗봇 지식 베이스 (신규 기능)
- 가이드 내용을 챗봇이 답변에 쓸 수 있는 질문·답변 형태로 재구성 — 메가하우스 40항목
  (기술: `knowledge-megahouse.md`, 답변마다 출처 탭 명시)
- 굿스마일·부시로드용 지식 베이스 별도 작성 — 30항목
  (기술: `knowledge-brand2.md`, 보상 조건이 브랜드마다 달라 파일 분리)
- 챗봇이 답하면 안 되는 항목(개별 유입 수, 정산 상태, 담당자 연락처 등)을 목록으로 명시
  (기술: 각 지식 파일 H 섹션, 프롬프트 주입용 금지 목록)

### 배포 자동화 (신규 기능)
- 가이드 수정 후 배포용 단일 파일을 명령어 한 줄로 다시 만들 수 있게 함
  (기술: `build-standalone.js`, CSS·JSX·이미지·React·Babel·웹폰트를 전부 인라인)
- 이미지를 파일 데이터 자체로 바꿔 넣어 인터넷 없이도 열리는 파일 생성
  (기술: `assets/*` 경로를 base64 data URI로 치환, 외부 요청 0건 확인)
- 내려받은 외부 파일을 재사용해 두 번째 실행부터 빨라짐
  (기술: `.vendor-cache/` 로컬 캐시, curl 경유 다운로드)
- 손으로 하던 원본↔배포본 동기화 작업 폐지
  (기술: 생성물 `standalone/`을 `.gitignore` 처리, 파생물은 저장소에서 제외)

### 설계 문서
- 구현 기준이 되는 설계도 작성 — 절대 원칙, 기술 결정, 비용, 약점까지 명시
  (기술: `PLAN.md`, 저지능 모델이 그대로 따라 구현할 수 있는 수준으로 구체화)
- 응답 모델을 Claude Sonnet 5로 확정
  (기술: `claude-sonnet-5`, 프롬프트 캐싱 최소 크기 1,024토큰으로 여유 확보)
