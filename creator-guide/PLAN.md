# creator-guide — 크리에이터 협업 가이드 + 문의 응대 챗봇

## 이 프로젝트가 하는 일

인플루언서·크리에이터 협업 가이드 페이지와, 그 가이드 내용만으로 답하는
문의 응대 챗봇. **목적은 실무자에게 오는 반복 문의를 줄이는 것.**

## 폴더 구성

```
creator-guide/
├─ index.html              # 메가하우스 가이드 (진입점)
├─ brand2.html             # 굿스마일·부시로드 가이드
├─ shared.jsx              # 메가하우스 — 가이드 내용(데이터)
├─ finalOption.jsx         # 메가하우스 — 화면 렌더링
├─ styles.css              # 메가하우스 — 스타일
├─ shared-brand2.jsx       # 굿스마일·부시로드 — 가이드 내용(데이터)
├─ finalOption-brand2.jsx  # 굿스마일·부시로드 — 화면 렌더링
├─ styles-brand2.css       # 굿스마일·부시로드 — 스타일
├─ assets/                 # 가이드에 쓰는 이미지
├─ standalone/             # 오프라인 단일파일 배포본 (이미지 내장)
├─ knowledge-megahouse.md  # 챗봇 지식 베이스 — 메가하우스
├─ knowledge-brand2.md     # 챗봇 지식 베이스 — 굿스마일·부시로드
└─ PLAN.md                 # 이 문서
```

두 브랜드 버전은 데이터·렌더링·스타일 파일이 완전히 분리되어 서로 영향이 없다.

## 절대 원칙 (챗봇)

1. **지식 베이스에 없는 내용은 답하지 않는다.** 추측·창작 금지.
   답을 모르면 "확인이 필요한 내용이라 담당자에게 문의 부탁드립니다"로 안내한다.
2. **답변에는 항상 출처(탭 이름)를 붙인다.** 사람이 검증할 수 있어야 한다.
3. **브랜드별로 챗봇을 분리한다.** 보상 조건이 서로 완전히 달라서 섞이면 오답이 난다.
   - 메가하우스: 유입 수 750 기준 차등 지급 (쿠폰 5만/10만 원)
   - 굿스마일·부시로드: 차등 없음, 홍보 상품과 동일 제품 지급
4. **매 질문을 완전히 새로 시작한다(stateless).** 대화가 길어지며 규칙이 흐려지는
   것을 막기 위해, 규칙 변경은 대화가 아니라 이 파일·지식 베이스 수정으로만 한다.

## 파일 수정 시 반드시 같이 고쳐야 하는 것 (동기화 규칙)

가이드 내용을 바꾸면 **연쇄로 고쳐야 하는 파일이 있다.** 하나라도 빠지면
"가이드에는 바뀌었는데 챗봇은 옛날 답을 하는" 상태가 된다.

| 바꾼 파일 | 같이 고쳐야 하는 것 |
|---|---|
| `shared.jsx` | `knowledge-megahouse.md` + `standalone/크리에이터 협업 가이드.html` |
| `shared-brand2.jsx` | `knowledge-brand2.md` + `standalone/크리에이터 협업 가이드 (굿스마일·부시로드).html` |

## 기술 선택 (정해둔 것)

- **RAG 안 씀.** 지식 베이스 분량이 작아서 매 요청마다 통째로 프롬프트에 넣는 게
  더 간단하고 정확하다. 검색이 실패해서 엉뚱한 답을 하는 경로 자체가 없어진다.
- **모델: Claude Haiku 4.5** — 문의 응대 수준에는 충분하고 가장 저렴하다.
- **배포: Vercel 서버리스** — 이 레포의 다른 프로젝트(`insta-gen`)와 같은 구조.
  API 키를 브라우저에 노출하지 않기 위해 서버를 거친다.
- **`vercel.json`의 `ignoreCommand`** 로 이 폴더가 바뀔 때만 재배포되게 제한한다.
