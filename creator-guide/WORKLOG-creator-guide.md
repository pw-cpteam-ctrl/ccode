## 2026-09-03

### 이벤트 보상 지급 기준을 오픈일 하나로 통일
- **문제** ▶ 팀장님 검토 후 최소 권장 기간과 선지급 기간을 조정할지 논의하다, 기존 안내 자체가
  산술적으로 성립하지 않는다는 것이 드러남
  - 이벤트 최소 7일 + 당첨자 정보 전달 3일 이내 = 10일인데, 지급은 7일 이내라고 안내돼 있었음
  - 문서마다 기준이 되는 날짜(업로드일 기준 / 오픈일 기준)가 서로 달랐음
- **처리** ▶ 기준을 오픈일 하나로 통일하고 지급 회차를 둘로 정리함
  - 당일 업로드가 원칙, 선지급 없음, 업로드 확인 후 지급
  - 오픈 후 7일 이내 업로드 확인 → 오픈 후 10일차에 일괄 지급
  - 7일을 넘기면 프리오더 정산 시점(오픈일 기준 약 40일)에 함께 지급
  - 이벤트 기간에 상한을 두지 않되 프리오더 기간 안에는 마무리하도록 안내
- **결과** ▶ 화면과 챗봇 지식베이스를 같은 기준으로 맞춤 (`shared.jsx`의 보상 안내,
  `knowledge-megahouse.md`의 F-TRACK·FE 항목)

### 경품 분할 예시 단락 삭제
- **문제** ▶ 이벤트 안내의 "경품은 이렇게 나눌 수 있어요" 단락이 경품을 잘게 쪼개도록
  유도하는 것처럼 읽힌다는 의견
- **처리** ▶ 화면과 챗봇에서 해당 단락을 통째로 삭제하고, 그 안에 있던 "이벤트를 진행해도
  유입 수에 따른 보상은 그대로"라는 설명만 다른 항목으로 옮김 (`EVENT_GUIDE.details`)

### 당첨자 정보 전달 기한 표현 변경
- **문제** ▶ "당첨자 정보 발표 후 3일 이내 전달"이라는 기한 표기가 부담을 준다는 지적
  - 앞서 지급 기준을 정리하면서 이 문장을 함께 봤다고 보고했으나 실제로는 남아 있었음
- **처리** ▶ 기한 없이 "발표 후 취합이 완료되면 공유해 주세요"로 바꿈

### 01 요약 카드에서 '3' 표현 정리
- **문제** ▶ 첫 화면 카드에 "3분", "3가지"가 반복돼 숫자만 눈에 들어오고 헷갈린다는 지적
- **처리** ▶ 시간 표기를 빼고 제목을 "먼저 봐두면 좋은 핵심 요약"으로, 안내 문구를
  "아래 포인트만 지키시면 나머지는 자유롭게 진행해주셔도 좋습니다"로 바꿈 (`GUIDE.opener`)

### 요청하지 않은 문장이 들어가 있던 것 삭제

- **처리** ▶ 해당 줄 삭제. 앞으로 요청받지 않은 문장은 살리지 않고, 없어져도 되는지 먼저 묻기로 함

### 라이브에 몇 시간 동안 반영이 안 되던 문제
- **문제** ▶ 커밋·푸시를 마쳤다고 보고했는데 실제 페이지에는 옛날 내용이 계속 보임
- **확인** ▶ 배포 플랫폼(Vercel)의 하루 배포 횟수 제한(100회)에 걸려 있었음
  - 이 저장소 하나에 배포 프로젝트가 7개 붙어 있어 커밋 1개마다 배포가 7개 만들어짐
  - 그중 6개는 "내 폴더는 안 바뀌었다"며 1초 만에 취소되지만, 취소된 것도 100회에 포함됨
  - 챗봇 문의가 들어올 때마다 로그가 커밋으로 올라가는 것도 같은 방식으로 횟수를 소모함
  - 중간에 인스타젠 프로젝트가 정상 배포되는 것을 보고 "한도가 아니다"라고 잘못 판단해
    GitHub 연동을 끊었다 다시 붙이는 등 불필요한 조치를 하게 만듦
- **처리** ▶ 사용자 컴퓨터에서 배포 도구로 직접 올려(`vercel --prod`) 밀려 있던 커밋 6개를 반영함
- **결과** ▶ 배포된 파일의 크기와 갱신 시각으로 반영을 확인함
  - 이후 커밋 1건은 한도에 걸려 아직 미반영 상태이며, 다음 날 한도가 풀린 뒤 올리기로 함
  - 재발 방지책으로, 요즘 손대지 않는 프로젝트 5개의 저장소 연결을 끊어 커밋당 배포를
    7개에서 2개로 줄이는 것을 안내함 (미적용)
  - "푸시 완료"까지만 확인하고 실제 페이지 반영을 확인하지 않은 것이 원인 파악을 늦춤

### 이벤트 페이지 전반 점검 후 정리

    서로 무관한 기준처럼 읽힘
  - 06 보상 탭은 "7일 이내 업로드 확인", 이벤트 페이지는 "9일 안에 당첨자 정보"인데 둘 다
    같은 10일차로 끝나 두 페이지를 오가면 혼동됨
  - 챗봇이 "크리에이터님이 보상을 받으시는 시점과 같습니다"라고 단정했으나, 실제로는 기준이

  - 챗봇의 "정보를 빨리 주실수록 경품도 빨리 전달됩니다"는 사실이 아님 — 지급 회차가 둘뿐이라
    5일차에 줘도 8일차에 줘도 결과가 같음 (`knowledge-megahouse.md` FE-4)
- **처리** ▶ 사실관계를 먼저 바로잡고, 중복 문장과 흐름을 함께 정리함
  - 지급 안내 첫 문장에 "발급 날짜는 크리에이터 보상과 같은 회차이고 기준만 다르다"를 명시
  - 9일에 "10일차 발급의 전날이라서"라는 이유를 붙임
  - "이벤트를 더 길게 진행하시는 경우"는 조건이 부정확해(짧게 해도 정보가 늦으면 정산 시점)
    "그 이후에 주신 경우"로 바꿈
  - 같은 말이 두 번 나오던 자리를 한 곳으로 모음 — 자유 안내, 담당자 공유, 프리오더 기간

  - 위아래 돌아가기 버튼의 문구가 똑같던 것을 구분함
- **결과** ▶ 아이폰 폭(410px) 브라우저로 이벤트 페이지를 열어 접힘 영역까지 펼쳐 확인했고

### 06 보상 탭 정리 — 상자 반복과 겹치는 문장
- **문제** ▶ 한 단락에서 상자가 네 번 반복돼 어수선하고, 같은 말이 여러 번 나온다는 지적
  - 회신 폼의 주의 안내가 흰 바탕에 테두리라 무언가 입력하는 칸처럼 보임
  - 넓은 화면에서 달력 아래 안내만 왼쪽 끝에 떨어져 보임
- **처리** ▶ 문구는 그대로 두고 배치와 색을 정리
  - 고른 결과와 확인 사항을 한 초록 상자로 합쳐 카드 아래로 내림 (`trk-picked`)
  - 주의사항과 FAQ 안내는 상자를 없애고 구분선 하나로 묶음 (`rwd-tail`)
  - 겹치던 문장 정리 — 탭 머리말이 제목을 되풀이하던 것, '변경·교환 불가'가 두 번 나오던 것,
    수령 방식을 고르라는 안내가 세 군데 있던 것
  - 주의 안내를 옅은 바탕에 왼쪽 선만 있는 모양으로 바꿔 입력칸처럼 보이지 않게 함 (`reply-warn`)
  - 달력과 그 아래 안내를 같은 폭으로 묶어 정렬 (`cal-block`)
- **결과** ▶ 브라우저로 확인 — 넓은 화면(720px)에서 173px 어긋나던 달력·안내가 왼쪽 끝 일치,
  "수령 방식/변경/교환"이 각각 한 번씩만 나오는 것까지 확인

### 06 수령 방식이 미리 골라져 있다는 지적

- **처리** ▶ 저장을 유지하기로 확인받아 코드는 그대로 둠
- **결과** ▶ 새 브라우저로 열면 아무것도 안 골라진 상태인 것 확인

  달라지는 대화·질문은 반드시 뒤에 오도록 구성. "지식 베이스의 모든 답변에는 출처가
  붙어있다"는 성질을 이용해, 답변에 출처가 없으면 코드가 정해진 안내 문장으로 바꿔치기하는
  안전장치(`groundAnswer`)를 별도 함수로 분리해 만듦. 외부 남용을 막기 위해 같은 출처에서
  온 요청만 받도록 검사(insta-gen의 로직을 복사, import는 안 함)하고 질문 길이도 500자로
  제한. 화면은 FAQ 탭 맨 아래 있던 기존 "문의 있어요" 입력창 자리를 챗봇으로 그대로 교체
  (`chat-widget.jsx`, `chat.css`) — Enter 전송, 대기 중 점 세 개 표시, 답변 옆 복사 버튼,
  출처를 누르면 해당 탭으로 이동, 실패해도 입력한 질문은 지우지 않음, 모바일 키보드 대응,
  처음 열었을 때 예시 질문 3개 노출까지 반영
- **결과**: 브라우저로 직접 조작해 14개 항목 확인 — 챗봇 렌더링, 예시 질문 클릭, 대기
  표시, Enter 전송, Shift+Enter 줄바꿈, 오류 시 입력 보존, 모르는 답변은 노란 배경으로
  구분, 출처 클릭 시 실제로 "02 업로드 순서 탭"으로 이동, 서버로 브랜드 값이 정확히
  전달됨. JS 오류 없음. API는 방어 로직 8종(GET 요청 거부, 외부 사이트발 요청 거부, 잘못된
  브랜드, 빈 질문, 501자 질문, 키 미설정 등) 확인했고, 마지막 "잘못된 키" 테스트는 실제로
  Anthropic 서버까지 도달해 SDK 연결과 지식 파일 읽기까지 같이 확인됨. 안전장치는 7가지
  입력(정상 답변·안내 문장은 유지, 출처 없는 답·빈 응답은 교체)으로 따로 검증함. 다만
  실제 API 키가 없어 답변 품질 자체는 아직 확인 못 함 — 키 등록은 요청해둔 상태

### package.json 추가로 배포 스크립트가 깨짐
- **무슨 문제/요청이 있었나**: 챗봇에 필요한 패키지(`@anthropic-ai/sdk`)를 쓰려고
  `package.json`을 새로 만들었는데, 이미 있던 배포용 파일 생성 스크립트를 돌리니 오류가 남
- **확인해보니**: `package.json`에 `"type": "module"`을 넣으면서 폴더 전체가 최신 문법
  기준으로 바뀌었는데, 먼저 만들어둔 `build-standalone.js`는 구식 문법(`require`)을 쓰고
  있어서 실행 자체가 안 됐음. 파일을 따로따로 만들다가 서로 영향을 주는 걸 놓친 것이
  원인 — 미리 못 잡은 이유는 새 파일을 추가할 때 이미 있는 스크립트에 미치는 영향까지
  같이 확인하지 않았기 때문
- **어떻게 처리했나**: `build-standalone.js`를 최신 문법(`import`)으로 고침
- **결과**: 다시 실행해서 정상적으로 배포용 파일 2개가 만들어지는 것까지 확인함
