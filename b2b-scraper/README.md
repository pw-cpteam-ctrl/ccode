# B2B 스크래퍼 (GoodSmile)

`product-sns-formatter`의 "① B2B에서 오늘 상품 가져오기" 버튼이 실제로 쓸 결과물
(`output.json` + 사진 파일들)을 만드는 도구. **팀원(비개발자)용 실행 방식**과
**개발자용 정찰(recon) 방식** 두 가지가 있음.

## ⚠️ 반드시 로컬(화면 있는) 컴퓨터에서 실행할 것

이 원격 개발 환경(화면 없는 샌드박스)에서는 실행할 수 없다 — 로그인 단계가 진짜 브라우저
창을 띄워서 사람이 직접 로그인해야 하고, 정찰/스크래핑 단계도 GoodSmile 쪽에서 이 환경의
IP를 막을 가능성이 있다. **아래 내용은 전부 각자 컴퓨터(Node.js 설치된 곳)에서 실행.**

---

## 배포/업데이트 — 팀원 PC에 어떻게 최초로 두고, 어떻게 최신 상태로 유지하나

**핵심: `main`에 push하면 그게 곧 배포다.** 사람이 파일을 옮기는 중간 단계가 없다.

```
개발(이 폴더) ──push──▶ main ──읽음──▶ /api/files (Vercel) ──받음──▶ 팀원 PC update.js
```

- **`api/files.js`(Vercel)가 배포 통로**다. 이 저장소의 `b2b-scraper` 폴더를 읽어서, 팀원에게
  필요한 파일만 골라 목록(JSON)으로 내려준다. 팀원 PC의 `update.js`가 그 목록을 받아 파일을
  덮어쓴다. 받는 파일이 전부 텍스트라 압축을 다룰 필요가 없어서 구조가 단순하다.
- **왜 GitHub에서 직접 받지 않나** (예전엔 `codeload` zip을 받았다):
  1. 팀원 파일 어디에도 개발 저장소 이름이 남지 않는다 — 보이는 건 vercel.app 주소뿐.
  2. zip 방식은 **압축을 푸는 순간 저장소의 다른 프로젝트 전부가 팀원 폴더에 실제 파일로
     풀린다**(곧 지워지지만 중간에 실패하면 남는다). 파일을 골라 받으면 그 문제가 없다.
  3. 예전엔 이 문제를 별도 배포 레포(`share`)로 우회했는데, 그건 **사람이 매번 파일을 옮겨야
     하는** 구조였다. 지금은 그 수동 단계가 사라졌으므로 `share`는 더 쓰지 않는다.
- **토큰이 필요 없다**: 원본 저장소가 공개라서 인증 없이 읽힌다. 그래서 "토큰이 만료돼
  배포가 조용히 멈추는" 실패 모드가 없다. (같은 이유로 GitHub Action 미러링도 채택하지 않았다 —
  토큰 만료 시 나도 사용자도 모르는 채 팀원만 옛 버전을 쓰게 된다.)
  → **저장소를 비공개로 바꾸면 이 endpoint에 토큰이 필요해진다.** 그때 `api/files.js`만 고치면 된다.
- **`update.bat`은 앞으로 바뀌지 않는다** — 노드를 부르기만 하는 껍데기다. CMD는 배치 파일을
  줄 단위로 읽으며 실행하므로 실행 중에 자기가 덮어써지면 오작동한다. 그래서 `update.bat`은
  배포 목록에서 제외(`api/files.js`의 `EXCLUDE`)하고, 실제 로직은 `update.js`에 뒀다. 노드는
  스크립트를 통째로 읽고 파일을 닫으므로 **자기 자신이 갱신돼도 안전하다.**
  → 즉 앞으로 업데이트 방식을 바꿔도 팀원이 손으로 파일을 갈 일이 없다.
- **업데이트는 아무것도 지우지 않는다**: `update.js`는 받은 파일만 덮어쓴다. `output/` 결과물,
  설치된 `node_modules`, 저장된 로그인(애초에 이 폴더 밖)은 건드리지 않는다. 그리고 받은
  내용을 **전부 검사한 뒤에야** 쓰기를 시작해서 "절반만 갱신된" 상태를 만들지 않는다.
- **업데이트 알림 방식 (자동 적용 안 함)**: `run.bat`을 실행하면 새 버전이 있는지 확인해서
  **안내 문구만 띄우고 평소대로 진행**한다(`check-update.js`). 실제 적용은 팀원이 `update.bat`을
  눌러야 일어난다. 자동 적용을 안 하는 이유는 검증 안 된 코드가 팀원에게 즉시 전파되면 내
  실수 하나가 그날 업무를 그대로 망치기 때문. 확인이 실패해도(인터넷 끊김 등) 실행은 절대
  막히지 않는다.
- **버전은 파일 내용의 해시**다(커밋 sha가 아님). 관계없는 커밋 때문에 "새 버전 있음"이
  헛되게 뜨는 걸 막기 위함 — 이 폴더 내용이 실제로 바뀔 때만 값이 바뀐다.
- **자체 점검**: `api/files.js`는 내려보낼 `.js`들이 `require`하는 같은 폴더 파일이 전부
  들어있는지 확인하고, 빠졌으면 **응답 자체를 실패시킨다.** 이 구조에서 가장 현실적인 사고가
  "새 파일을 추가했는데 배포 목록에서 빠져 팀원 쪽이 `Cannot find module`로 죽는 것"이라서,
  팀원이 겪기 전에 여기서 터지게 만들었다.
- **팀원용 문서는 `사용법.md`로 분리**했다. 이 README(개발용)는 내부 판단 근거와 저장소 구조가
  적혀있어 배포 목록에서 제외된다.
- **로그인 유출은 구조적으로 불가능하게 해뒀다**: 로그인 데이터(전용 크롬 프로필)를 이
  저장소 폴더가 아니라 **저장소 밖**(`%LOCALAPPDATA%\b2b-scraper\chrome-profile`)에 저장한다
  (`profile-dir.js`). 예전엔 `b2b-scraper/chrome-profile/`에 뒀어서 "안 새는 근거"가
  `.gitignore` 한 줄 + 사람의 주의력뿐이었는데, 공개 저장소에서 그건 실수 한 번이면 굿스마일
  B2B 로그인이 전세계에 공개되는 사고였다. 지금은 git이 볼 수 있는 범위 밖이라 그 사고가
  애초에 성립하지 않는다.
- **최초 1회**: 팀원에게 이 폴더를 통째로 전달(zip이든 뭐든 한 번). 이후로는 `update.bat`
  더블클릭으로 유지된다.
- **zip 방식에서 이 방식으로 전환할 때 (1회 한정)**: 팀원 PC에 `update.bat`, `update.js`,
  `update-source.js` **3개를 함께** 넣어줘야 한다. 새 `update.bat`은 `update.js`를 부르는데
  그게 아직 팀원 PC에 없고(예전 zip 배포엔 없던 파일), `update.bat`은 배포 목록에서 제외돼
  있어서 스스로 내려올 수도 없기 때문. 3개 중 하나라도 빠지면 `update.bat`이 무슨 파일이
  빠졌는지 알려주고 멈춘다(`:missing` 분기) — 원인 모를 `Cannot find module`로 죽지 않게 해뒀다.
  전환 이후엔 `update.js`/`update-source.js`가 매 업데이트마다 자동으로 갱신된다.
- **주소를 바꾸면 안 되는 이유**: 배포 주소는 `update-source.js` 한 곳에만 있다. 이게 바뀌면
  팀원 PC의 파일은 옛 주소를 들고 있어서 **스스로 갱신할 수 없다**(= 수동 교체가 다시 필요).
  Vercel 프로젝트 이름/도메인은 되도록 건드리지 말 것.

## 팀원(비개발자)용 — 더블클릭 한 번

0. **(실행 중 "새 버전이 있습니다" 안내가 떴으면)** 그 작업이 끝난 뒤 `update.bat` 더블클릭 →
   몇 초 안에 최신 코드로 갱신됨. (안내가 안 떴으면 신경 쓸 필요 없음)
1. 이 폴더(`b2b-scraper`)를 통째로 받는다.
2. `run.bat`을 더블클릭 (원하면 바탕화면에 바로가기 만들어서 "굿스마일 상품 가져오기"로
   이름 붙여도 됨).
3. 검은 콘솔 창이 뜨고 진행상황이 한국어로 표시됨. 타이핑할 건 없음.
   - Node.js가 없으면 설치 안내가 뜸 → nodejs.org에서 LTS 설치 후 다시 더블클릭.
   - 최초 실행이면 "준비 중..." 문구와 함께 자동으로 라이브러리를 설치함 (1~2분).
4. 크롬 창이 뜨면:
   - **이미 로그인된 적 있으면** → 로그인 세션을 기억하고 있어서 아무것도 안 해도 자동으로
     넘어감.
   - **처음이거나 세션이 만료됐으면** → 그 창에서 GoodSmile 아이디/비밀번호로 로그인. 로그인
     완료되면 (엔터 칠 필요 없이) 자동으로 감지해서 이어서 진행됨.
5. 완료되면 콘솔에 "완료: N건 -> ..." 문구가 뜨고, `output/<발표일>/output.json`과
   `output/<발표일>/photos/` 폴더가 생성됨. 아무 키나 눌러 창을 닫으면 됨.
6. product-sns-formatter 페이지의 "🔄 B2B에서 오늘 상품 가져오기" 버튼을 누르고, 방금
   만들어진 `output.json` 파일과 `photos/` 폴더 안의 사진 파일들을 **함께 선택**하면
   (Ctrl+클릭으로 다중 선택, 또는 폴더째 드래그) 상품 목록에 자동으로 채워진다.

### 어느 날짜분을 받게 되나 (전날 18시에 다음날 상품이 올라오는 문제)

GoodSmile B2B는 **전날 18시쯤에 다음날 발표분을 미리 공개**한다. 그래서 "PC 시계로 오늘"을
기준으로 잡으면 저녁에 돌렸을 때 이미 올라와 있는 내일 상품을 통째로 놓친다. 그렇다고
"18시 넘으면 내일로 치기"처럼 시계로 추측하면, 공개가 늦어진 날엔 아직 없는 날짜를 찾아
0건이 된다.

그래서 이 도구는 시계를 안 본다 — **사이트에 실제로 올라와 있는 발표일 중 가장 최신 것**을
받는다.

- `run.bat` (평소) → 사이트에 올라온 **가장 최신 발표일**분. 아침에 돌리면 그날치, 18시
  이후에 돌리면 다음날치가 자동으로 잡힌다. **타이핑할 건 없다.**
- `run-pick-date.bat` (가끔) → 받을 수 있는 발표일을 목록으로 보여주고 번호로 고르게 한다.
  지난 날짜분을 다시 받고 싶을 때 쓴다. 엔터만 치면 가장 최신으로 진행.
  ```
  받을 수 있는 발표일:
    1) 2026년 7월 30일 — 18건   ← 가장 최신
    2) 2026년 7월 29일 — 12건
    3) 2026년 7월 28일 — 9건

  번호를 고르고 엔터 (엔터만 치면 1번):
  ```
- 결과 폴더 이름은 **실행한 날이 아니라 받은 발표일**이다(`output/2026-07-30/`). 그래서
  18시 이후에 돌려도 다음날 폴더로 정확히 들어가고, 같은 날짜를 다시 받으면 같은 폴더가
  갱신될 뿐 다른 날짜분과 섞이지 않는다.
- **주말처럼 새 발표가 없는 날** 돌리면 이미 받은 날짜가 그대로 다시 잡힌다. 이때는
  "이 날짜는 전에 받은 적이 있어요"라고 알려주고 같은 폴더를 갱신한다(사고 아님).
- **정직한 한계**: 사이트 첫 화면에서 밀려난 오래된 날짜는 이 방식으로 못 받는다. 첫 화면에
  최근 며칠~몇 주치가 같이 뜨는 건 확인했지만, 그보다 오래된 목록을 어떻게 불러오는지는
  아직 정찰(recon)하지 않았다. 필요해지면 `recon.js`로 과거분 목록 페이지를 먼저 확인해야
  한다.

**로그인이 꼬였을 때**: 로그인이 계속 실패하거나 이상하게 막히면 `reset-login.bat`을
더블클릭하면 저장된 로그인이 지워진다. 그 뒤 `run.bat`을 다시 실행하면 크롬 창이 새로 떠서
처음부터 로그인할 수 있다. (로그인 데이터가 저장소 밖 숨은 경로에 있어서 직접 찾아가 지우기
어렵기 때문에 이 버튼을 따로 뒀다.)

**정직한 한계**: `.bat`이라 실행 중 검은 콘솔 창은 뜬다(진행상황 표시용). 다만 거기 뭘
입력할 필요는 없고, 실제 조작(로그인)은 전부 크롬 창에서 일어난다. 콘솔 창 자체를 없애려면
exe/GUI 포장이 필요한데, 이번 프로젝트 규모엔 오버킬로 판단해 `.bat`으로 마무리함.

## 개발자용 — 사이트 구조 정찰 (`recon.js`, 완료됨)

실제 GoodSmile B2B 사이트(2026-07-27 기준)를 정찰한 결과:
- 임베디드 JSON(`__NEXT_DATA__` 등)이 전혀 없는 순수 서버 렌더링 HTML → `scrape.js`는
  화면 요소를 직접 읽는 방식(DOM 파싱, `page.locator`)으로 필드를 뽑는다.
- 상품 목록 = 로그인 후 뜨는 홈 화면(`https://www.goodsmile.com/b2b/en`) 자체가 매일
  갱신되며, 신상품이 `/b2b/en/product/<숫자ID>` 링크로 나열됨. 이 홈 화면엔 **최근 며칠~몇
  주치가 섞여** 있다(정찰 당시 필터 전 117건).
- 각 상품 카드에 **발표일이 데이터로 박혀있다**:
  `<li class="p-top__products__item" data-guidance_date="20260730">`. 그래서 별도 검색/필터
  페이지 없이 이 속성만 읽어서 "받을 수 있는 발표일 목록"을 만들 수 있다 (`target-date.js`).
  전날 18시에 다음날분이 미리 공개되는 사이트 특성 때문에 PC 시계 기준으로 날짜를 정하면
  안 되고, 이 속성이 유일하게 신뢰할 수 있는 기준이다.
- 상세 페이지는 `.b-product-info__title`(제목), `.b-product-info__unit--date`(발매월 등),
  `#section_spec`(시리즈/사이즈/제조사), `.c-photo-variable-grid img`(사진) 구조를 그대로
  읽는다. (가격/저작권/카톤당 수량은 팀 실사용에 필요 없어서 수집하지 않는다.)
- 로그인 필요 시 실제로 `/login` 경로로 리다이렉트됨 (`LOGIN_URL_PATTERN`과 일치 확인됨).

사이트 구조가 나중에 바뀌면 다시 정찰해서 `scrape.js`를 갱신해야 한다:

```bash
cd b2b-scraper
npm install
node recon.js <다시 확인하고 싶은 페이지 URL>
```

`scrape.js`와 같은 전용 크롬 프로필(저장소 밖 — `profile-dir.js`)을 공유하므로, `scrape.js`를
먼저 한 번 돌려서 로그인해뒀다면 `recon.js`는 로그인 없이 바로 정찰 가능. `recon-output/`에
그 페이지의 HTML 전체와 스크린샷이 저장되고, 터미널에 마커·링크 목록이 출력된다.

---

## 설계 메모

- **세션 기억 방식**: 로그인 스크립트를 따로 두지 않고 `scrape.js`(및 `recon.js`) 자체가
  전용 크롬 프로필(저장소 밖 경로 — `profile-dir.js`)로 세션 유무를 확인 → 없거나 만료되면 로그인
  창을 띄우고 URL 변화로 로그인 완료를 자동 감지 → 있으면 곧바로 스크래핑, 한 흐름으로 처리.
  (기존에 쓰던 "터미널에서 엔터 치면 storageState 저장" 방식은 비개발자에게 낯설어서 폐기.)
- **가벼운 설치**: `playwright` 대신 `playwright-core`를 의존성으로 사용 — 팀원 PC에 이미
  깔린 진짜 크롬(`channel: 'chrome'`)을 그대로 쓰므로 브라우저 ~300MB 자동 다운로드가 없고,
  최초 `npm install`이 수 MB 수준으로 가벼움.
- 봇탐지 위장(`applyStealth` 등)은 옮기지 않았음 — B2B 업무포털은 인스타/X처럼 엄격하지
  않을 가능성이 높아서. 로그인이 자꾸 자동화로 의심돼 막히면 그때 강화하면 됨.
- **`run.bat`에는 한글을 절대 넣지 말 것 (전부 영어/ASCII).** 한국어 윈도우 CMD가 `.bat`을
  읽는 코드페이지와 파일 실제 인코딩이 어긋나면 한글이 깨지고, 깨진 바이트가 명령줄 파싱까지
  망가뜨려 `'...'은(는) 내부 또는 외부 명령...` 에러가 난다 (실제로 한 번 겪음). ASCII만 쓰면
  어떤 코드페이지로 읽어도 안 깨져서 원천 차단됨. 사용자에게 보여줄 한글 안내문은 `.bat`이
  아니라 `scrape.js`(node, UTF-8)에서 출력 — `.bat`의 `chcp 65001`이 그 출력을 콘솔에 제대로
  표시해줌.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `run.bat` | 팀원용 더블클릭 런처 — 사이트에 올라온 가장 최신 발표일분을 받음 (실행 전 업데이트 유무만 확인해서 알려줌) |
| `run-pick-date.bat` | 받을 발표일을 목록에서 번호로 골라 받는 런처 (지난 날짜분 다시 받을 때) |
| `update.bat` | 업데이트 런처 — 노드를 부르기만 하는 껍데기 (**배포 목록에서 제외**: 실행 중 자기 덮어쓰기 방지, 팀원이 손으로 갈아야 하는 유일한 파일) |
| `update.js` | 실제 업데이트 로직 — 목록 받아 검사 → 파일 덮어쓰기 → 필요시 `npm install` → 버전 기록. 아무것도 지우지 않음 |
| `update-source.js` | 배포 주소를 정의하는 유일한 곳 (`update.js`·`check-update.js` 공용) |
| `api/files.js` | **배포 통로(Vercel)** — 이 저장소를 읽어 팀원용 파일만 골라 JSON으로 내려줌 + 누락 파일 자체 점검 |
| `vercel.json` | 이 폴더만 배포/재배포되게 하는 설정 (**배포 목록에서 제외**) |
| `사용법.md` | **팀원용** 문서 (이 README는 개발용이라 배포 목록에서 제외) |
| `reset-login.bat` | 로그인이 꼬였을 때 저장된 로그인을 지우는 초기화 버튼 |
| `scrape.js` | 메인 스크립트 — 세션 확인/로그인 대기 → 발표일 선택 → DOM 파싱으로 실제 필드 추출까지 한 번에 |
| `target-date.js` | "어떤 발표일분을 받을지" 정하는 순수 로직 (시계를 안 쓰는 이유가 여기 적혀있음) |
| `profile-dir.js` | 로그인 데이터(크롬 프로필) 저장 위치를 정의하는 유일한 곳 — **저장소 밖** 경로 |
| `check-update.js` | 새 버전 유무 확인 후 안내만 출력 (자동 적용 안 함, 실패해도 실행 안 막음) |
| `reset-login.js` | `reset-login.bat`이 호출하는 실제 삭제 로직 (한글 안내 출력) |
| `browser-stealth.js` | 전용 크롬 프로필 세션 열기 + 자동 로그인 감지 도우미 |
| `recon.js` | 페이지 구조 정찰 (사이트 구조 바뀌었을 때 재확인용) |
| `download-image.js` | 로그인 세션으로 사진 다운로드 |
| `format-output.js` | 필드를 output.json 형태로 조립 |
| `friendly-error.js` | 오류 메시지를 팀원이 읽을 수 있는 안내문으로 바꿈 (원인 불명이면 "캡처해서 담당자에게") |
| `os-helpers.js` | 결과 폴더 경로 클립보드 복사 + 탐색기로 열기 (실패해도 스크래핑엔 영향 없음) |
