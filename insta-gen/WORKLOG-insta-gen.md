## 2026-08-03

### 세부 항목(토비마스 등)을 고르면 타이틀이 그 세부명으로 바뀌어버리는 문제
- **무슨 문제/요청이 있었나**: 진격의 거인 컬렉션 피규어 관련 원문을 붙여넣고 드롭다운에서
  컬렉션 피규어를 골랐는데도, 화면엔 드롭다운에 있지도 않은 "진격의거인컬렉션피규어토비마스"가
  대신 골라지고 수정도 안 되는 증상 재신고. 이후 사용자가 규칙을 직접 제시함 — 세부 항목이
  뭐가 나오든 일단 대분류(룩업/스케일/컬렉션 피규어/컬렉션 굿즈/메가캣) 먼저 고정되고, 세부는
  제품명 쪽에 반영돼야 한다는 것
- **확인해보니**: G.E.M. 계열만 "그룹은 고정, 세부(테노히라 등)는 `data-prefix`로 별도 전달"
  구조로 돼 있었고, 나머지 그룹(룩업/스케일/컬렉션 피규어/컬렉션 굿즈/메가캣)은 토비마스 같은
  세부 항목이 그 자체로 독립된 라인값으로 드롭다운·사전에 등록돼 있어서, 그걸 고르면 타이틀
  자체가 그 세부명으로 통째로 덮어써지던 게 원인
- **어떻게 처리했나**: 전 그룹에 G.E.M.과 동일한 "그룹 고정 + 세부는 옵션의 `data-prefix`로"
  패턴을 통일 적용. 사전 데이터(`dict.js`)도 그룹 감지용 목록(`LINES`)과 세부 감지용 목록
  (`LINE_DETAILS`, 그룹 일치 확인까지 같이 함)으로 분리해서 자유입력 파싱(`parseJP()`)도 같은
  방식으로 고침. 이 과정에서 이전에 잘못 만들어뒀던 "세부 라인 표시용 체크박스 + 전용 작은
  핑크 글씨 줄" 기능은 완전히 제거함(사용자가 원한 적 없던 기능이었음)
- **결과**: 룩업/G.E.M./스케일/컬렉션 피규어/컬렉션 굿즈/메가캣 각 그룹에서 세부 항목을
  드롭다운으로 직접 골라보고, 같은 세부 키워드가 든 원문을 자동 파싱(무료 채우기)으로도
  넣어봐서 타이틀엔 항상 대분류만 나오고 세부는 제품명 쪽에 붙는 것까지 캔버스 스크린샷으로
  확인. `main`에 반영 완료

### 카드 이미지 안 세부+캐릭터 표시 규칙 확정 (여러 차례 오해 주고받음)
- **무슨 문제/요청이 있었나**: "세부가 있으면 제품명 앞에 자동으로 붙어야 한다"는 요청을 여러
  형태로 반복 설명받음 — 캐릭터 1명이면 세부+캐릭터를 한 줄로 합치고("테노히라 나미카제
  미나토"), 캐릭터가 여러 명이면 세부는 자기 줄에("토비마스"), 캐릭터들은 가운뎃점(·)으로
  이어붙인 한 줄로("에렌·미카사·아르민·리바이·한지") 나오되 이 캐릭터 줄만 체크박스로
  작게/원래크기 전환돼야 한다는 것
- **확인해보니**: 처음엔 체크박스를 "글자가 폭에 다 안 들어갈 때만 자동으로 줄이는" 방식으로
  만들었는데, 짧은 이름 몇 개는 애초에 한 줄에 다 들어가버려서 체크해도 화면이 똑같다는 신고를
  받음 — 버그가 아니라 "줄일 필요가 없는 케이스"였지만, 사용자의 원래 의도는 "체크하면 무조건
  확실히 작아지는 3번째 크기 단계"였던 것으로 재확인됨
- **어떻게 처리했나**:
  - 세부(`state.linePrefix`) 유무·캐릭터 수에 따라 제품명 블록을 다르게 조립하도록 렌더링
    함수(`render()`)를 다시 짬 — 세부 없으면 지금처럼, 세부+1명이면 한 줄 병합, 세부+여러명이면
    세부 줄과 캐릭터 목록 줄을 분리
  - 캐릭터 목록 줄이 폭을 넘으면(체크박스를 껐을 때) 잘라내지 않고 자동으로 여러 줄에 나눠
    담게 함(`wrapLine()`), 줄 수가 늘어나 푸터와 겹칠 것 같으면 전체 줄 간격·글자 크기를 같이
    줄여서 안 겹치게 함
  - 체크박스는 "안 들어갈 때만 줄임" 대신 "제품명 크기의 60% 고정 크기"로 바꿈(`CHAR_SHRINK_RATIO`)
    — 이미 한 줄에 들어가는 짧은 이름이어도 체크하면 눈에 띄게 작아짐. 그래도 안 들어가면 더
    줄여줌
  - 체크박스는 새 원문/슬롯을 불러올 때마다 항상 꺼짐으로 리셋되게 함(`state.charShrink`는
    로컬 저장소에 저장하지 않음)
  - 세부 텍스트를 드롭다운이 자동으로 채워주기만 하고 직접 고칠 방법이 없어서 "토비마스 (6종
    세트)"처럼 부가 설명을 못 붙인다는 지적을 받고, 별도 입력창(`#t_lineprefix`)을 새로 만들어
    드롭다운 선택 시 자동으로 채워지되 그 위에서 직접 수정 가능하게 함
  - 룩업/G.E.M.의 세부(의상·소품·미니어처·판초·테노히라·프레셔스·캐럿)는 단어만 보면 어느
    그룹인지 안 보여서("의상 바쿠고") 캔버스 이미지에서만 그룹명을 붙여 표시하게 함("룩업 의상
    바쿠고", "G.E.M. 테노히라 나미카제 미나토") — 원고(캡션) 텍스트는 1줄에 이미 그룹명이 있어
    그대로 유지. 토비마스처럼 그 자체로 고유한 이름인 다른 그룹 세부는 손대지 않음
- **결과**: 각 케이스(세부 없음/세부+1명/세부+여러명, 체크박스 켬/끔, 캐릭터를 쉼표·슬래시로
  구분해 넣은 경우)를 실제 캔버스 스크린샷으로 다 찍어서 확인. `main`에 반영 완료

### 원고(캡션) 2번째 줄이 1번째 줄과 똑같은 내용을 또 보여주는 문제
- **무슨 문제/요청이 있었나**: 나루토 원문으로 무료 채우기를 돌려보니, 1번째 줄에 이미
  "나루토 질풍전 룩업"이라고 나왔는데 2번째 줄에 세부/접두어 없이 "룩업"만 또 나오는 게
  이상하다는 지적. 이어서 "IP명이 길어서 약칭을 쓰는 작품이면 2번째 줄엔 원래 IP명 풀네임이
  나와야지 시리즈명이 뜬금없이 왜 나오냐"는 지적도 이어짐
- **확인해보니**: 2번째 줄(`titleB`)이 "세부가 있든 없든 시리즈명+접두어+약칭"을 무조건 다시
  찍어내는 구조라, 접두어가 없을 때(세부 없음)는 1번째 줄과 완전히 중복된 내용만 보여주고
  있었음. 사용자가 정리해준 원칙은 "2번째 줄부터는 1번째 줄과 안 겹치는 값만 보여준다"는 것
- **어떻게 처리했나**: 1번째 줄(`headTitle`) 자체를 "약칭 쓰는 작품이면 약칭+시리즈, 아니면
  풀네임+시리즈"로 통일해서 항상 시리즈까지 압축해 넣게 하고, 2번째 줄부터(`infoLines`)는
  세부가 있으면 세부만(시리즈는 1줄에 이미 있으니 반복 안 함), 약칭을 쓴 작품이면 거기에
  더해 풀네임을(1줄엔 약칭만 있고 풀네임이 아직 안 나왔으므로) 순서대로 추가하고, 둘 다 없으면
  이 줄 자체를 아예 생략하도록 바꿈
- **결과**: 사용자가 준 예시 3개(히로아카+룩업, 가히리+G.E.M.+테노히라, 은혼+메가캣 찰싹)를
  실제로 다 돌려서 의도한 그대로 나오는 것 확인 후 `main`에 반영

### 팀원 PC에서 배포한 지 며칠 지난 옛날 버전이 계속 보이는 문제
- **무슨 문제/요청이 있었나**: 본인 PC에선 최신 버전이 잘 보이는데 팀원 PC에선 하드리프레시를
  해도 며칠 전 버전이 그대로 보인다는 신고
- **확인해보니**: 배포 주소에 직접 요청을 보내 응답 헤더를 확인한 결과 `cache-control: public,
  max-age=0, must-revalidate`로 캐싱을 이미 강하게 막아두고 있었고, 실제 배포된 내용도 최신
  변경사항이 다 반영돼 있음을 확인함 — 서버·배포 자체는 문제가 없었고, 팀원 PC나 그 네트워크
  구간(회사 프록시 등 중간 장비)에서 캐시가 걸리고 있는 것으로 추정됨(팀원 PC를 직접 볼 수는
  없어 완전히 확정하지는 못함)
- **어떻게 처리했나**: 정확한 원인 진단 없이도 바로 되는 방법으로, 허브 페이지(`index.html`)의
  "인스타 카드 생성기" 카드 링크에 페이지를 열 때마다 자동으로 새 타임스탬프를 붙이게 함
  (`?v=` + `Date.now()`) — 고정된 값(`?v=2` 등)을 박아두면 그 값 자체가 나중에 다시 캐싱될 수
  있어서, 항상 바뀌는 값으로 매번 새 요청으로 인식되게 함
- **결과**: 허브를 거쳐 들어오는 한 이 문제가 계속 예방됨을 확인. `main`에 반영. 팀원이 과거에
  받은 링크를 직접 북마크해뒀다면 그 링크는 여전히 예전 방식이라, 허브를 통해 들어오도록
  안내가 필요함

### PNG 다운로드 파일명이 항상 "insta-card.png"로 고정이던 것
- **무슨 문제/요청이 있었나**: 다운로드할 때 파일명이 항상 똑같아서, ②작품명+③시리즈/라인을
  조합해 자동으로 파일명이 되게 해달라는 요청. 한글이 깨지지 않아야 한다는 조건도 같이 받음
- **어떻게 처리했나**: 작품명과 시리즈/라인을 합쳐 파일명을 만드는 함수(`buildDownloadName()`)를
  추가해서 다운로드 버튼 클릭 시 이 이름을 쓰게 함(예: "은혼_G.E.M. 시리즈.png"). 파일
  시스템에서 못 쓰는 특수문자만 제거하고, 한글은 그대로 자바스크립트 문자열로 넣음(직접
  `encodeURIComponent`로 인코딩하면 오히려 `%XX`가 파일명에 그대로 남을 수 있어 하지 않음)
- **결과**: 콘솔에서 실제로 함수를 호출해 한글이 안 깨지고 정확히 나오는 것까지 확인함. 다만
  자동화 테스트 도구(Playwright)의 headless 브라우저 한계로 실제 "저장" 대화상자의 파일명까지는
  자동 검증하지 못해, 그 부분은 한계로 남겨두고 사용자가 직접 한 번 다운로드해서 확인하기로 함

### 자동 학습 파이프라인이 실제로 잘 작동하는지 재확인
- **무슨 문제/요청이 있었나**: "AI로 채우기를 쓸수록 무료 사전이 알아서 똑똑해지는 기능이 지금 정상 작동하는 게 맞냐"는 질문
- **확인해보니**: 라이브 사이트에 실제로 테스트 문구를 두 번 보내서 끝까지 직접 확인 — 첫 호출에서 일본어 원문 그대로 표기(`workJp`/`productJp`)가 잘 나오고, 같은 짝이 두 번째로 나오는 순간 학습 데이터가 배포와 분리된 `insta-gen-data` 브랜치에 정확히 쌓이며, `main`은 전혀 건드리지 않음을 확인함
- **어떻게 처리했나**: 테스트로 만든 가짜 데이터(`파이프라인 검증용 테스트` 등)는 실제 사전을 오염시키지 않도록 바로 삭제
- **결과**: 정상 작동 확인됨 — 테스트 데이터도 깨끗이 정리됨

### 허브 페이지로 들어오면 AI로 채우기가 항상 실패하는 문제
- **무슨 문제/요청이 있었나**: "AI로 채우기 실패: 서버 오류 (405)"가 뜨고 전혀 도움을 못 받는다는 신고
- **확인해보니**: 실제 배포 주소(`ccode-omega.vercel.app`)에 직접 접속하면 정상 동작했지만, 사용자는 허브 페이지(`pw-cpteam-ctrl.github.io/ccode/`)를 거쳐 들어오고 있었음. 허브는 정적 파일만 서빙하는 GitHub Pages라 서버 기능(`/api/parse`)이 아예 없고, 이 경로로 들어온 페이지가 그 주소로 요청을 보내면 GitHub Pages가 "POST 지원 안 함(405)"으로 응답하던 것이 원인 — 즉 코드 버그가 아니라 잘못된 경로로 들어와서 생긴 문제
- **어떻게 처리했나**: 허브 페이지의 "인스타 카드 생성기" 카드 링크를 상대경로(`insta-gen/index.html`)에서 실제 Vercel 배포 절대주소(`https://ccode-omega.vercel.app/`)로 변경. 다른 카드들도 서버 기능이 필요한지 점검했고, 유일하게 필요했던 "상품 SNS 포맷터" 카드는 이미 절대주소였음을 확인
- **결과**: `main`에 반영 후 GitHub Pages 재빌드까지 확인, 허브를 거쳐 들어와도 AI로 채우기가 정상 작동함

### 슬롯+캐싱 기능 코드를 다른 프로젝트에서 재사용하고 싶다는 요청
- **무슨 문제/요청이 있었나**: insta-gen에 있는 "이전 입력 5칸 캐시" 기능을 다른 프로젝트에도 붙이고 싶다며 관련 코드만 간단히 공유해달라는 요청
- **어떻게 처리했나**: localStorage 기반 슬롯 저장/복원/렌더링 코드(HTML+CSS+핵심 함수)를 정리해서 채팅으로 전달. 프로젝트마다 다른 부분(현재 화면 상태를 스냅샷으로 만드는 부분, 슬롯 클릭 시 복원하는 부분)은 별표로 표시해 그 프로젝트 사정에 맞게 고치도록 안내
- **결과**: 코드만 전달, insta-gen 자체는 변경 없음

### 화면 레이아웃 전면 개편 (여러 차례 목업으로 검토 후 반영)
- **무슨 문제/요청이 있었나**: 팀원이 실제로 써보니 각 칸이 무슨 역할인지 감을 못 잡고, 화면 배치도 답답하고 비효율적이라는 지적. 요청 사항이 많고 복잡해서 "코드로 바로 만들지 말고 그림으로 미리 보여달라"는 요구가 있었음
- **어떻게 처리했나**: 실제 코드/스타일 그대로 복사한 임시 목업 파일을 만들어 Playwright로 스크린샷을 찍어가며 여러 차례 검토받음. 중간에 손그림 주석을 오독해 엉뚱하게 고친 적이 여러 번 있었고("2열 분리"로 잘못 이해했다가 "박스 자체를 분리하라"는 뜻이었음이 뒤늦게 밝혀짐 등), 그때마다 사용자가 다시 스샷에 표시해준 내용을 재확인하며 바로잡음. 최종 확정된 내용:
  - 카드 미리보기를 75%로 축소하고 그 옆에 이전 입력 슬롯 5칸을 항상 표시 (빈 슬롯도 자리를 차지해서 기능이 있다는 걸 안 써봐도 알 수 있게)
  - "텍스트 입력" 칸을 미리보기 바로 밑으로, "원고(캡션)" 칸을 오른쪽으로 서로 위치를 바꿈
  - "사진 올리기"와 "원문 입력"을 한 박스 안에 가로로 나란히 배치해서 화면 높이를 줄임 (사진 칸 높이는 버튼 줄 끝나는 지점에 정확히 맞춤)
  - "두 버튼이 뭐가 다른지" 설명은 별도의 독립된 박스로 분리 (원래는 흰 박스 안에 있었는데 안 쓴 걸 잘못 알아듣고 처음엔 2열로 쪼갰다가 다시 되돌리고 박스 자체를 분리함)
  - 각 칸 제목 밑에 무슨 역할인지 알려주는 설명 문구를 크게(16px, 굵게) 추가
  - 헤드라인·작품명 입력칸을 가로 2열로 배치
  - 진행 중 슬라이더가 카드 밖으로 튀어나가는 버그, 미리보기 밑 안내문구가 캔버스랑 안 맞고 한쪽으로 쏠리는 버그를 추가로 발견해 같이 수정
- **결과**: 실제 파일에 반영 후 로컬에서 Playwright로 슬롯 채우기·복원·삭제 기능이 다 정상 작동하는지, PNG 다운로드용 실제 해상도(1080×1350)가 미리보기 축소와 무관하게 그대로인지 직접 확인. `main`에 커밋/배포하고 라이브 사이트에서도 반영된 것 확인함
