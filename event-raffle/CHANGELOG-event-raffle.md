## 2026-09-17 (V1.30 로컬 실행기 2차 전수점검)

> 이번 변경은 **로컬 실행기(`event-raffle/local/`)에만** 해당한다. 인터넷에 올라간
> 추첨기(`index.html`)는 한 글자도 바뀌지 않았다.

### 버그 수정
- **수집을 끝내고도 결과가 통째로 유실되던 문제 수정**
  (기술: 브라우저 `close()`가 멈추면 수집기 프로세스가 종료되지 않아 서버의 `close`
  이벤트가 안 와서 `작업.결과`가 설정되지 않고 UI가 영구 "진행 중" 상태로 남음.
  `login-session.js`에는 있던 강제 종료 안전장치가 `collect-instagram.js`에 빠져 있었음.
  stdout 드레인 콜백 뒤 `process.exit` + 3초 백업 타이머를 추가하고, 서버에도
  `__RESULT__` 수신 후 20초 워치독을 걸어 결과만 회수하고 정리하도록 함.
  `성공` 판정도 `코드 === 0 || Boolean(작업.결과)`로 변경)
- **수집 중 탭을 닫으면 완료된 결과를 회수할 수 없던 문제 수정**
  (기술: `끝` SSE 이벤트를 놓치면 결과를 가져올 경로가 없었음. `/api/local/status`에
  `결과id`를 추가하고, 화면이 받아간 id를 `localStorage`에 남겨 미수신 결과일 때만
  "직전 수집 결과 불러오기" 버튼을 노출)
- **진행 상황 로그가 재연결마다 중복 누적되던 문제 수정**
  (기술: SSE 연결 시 `작업.로그`를 줄 단위로 재전송 → 클라이언트가 append 하며 중복.
  `{지난로그: [...]}` 단일 메시지로 보내고 클라이언트가 `textContent`를 교체)
- **중복 실행 시 스택 트레이스가 노출되던 문제 수정**
  (기술: `app.listen`에 `error` 핸들러가 없어 EADDRINUSE가 uncaught로 터짐 →
  한국어 안내 후 `exit(1)`)
- **`start.bat` 첫 줄이 실행되지 않던 문제 수정**
  (기술: 파일 선두 UTF-8 BOM(`EF BB BF`) 때문에 cmd.exe가 `@echo off`를 명령으로
  오인 → BOM 제거. 더불어 `where node` / `npm install` / `playwright install`
  실패를 `errorlevel`로 검사해 한국어 안내 후 중단)

### 안정성
- SSE 전송을 `try/catch`로 감쌈 (끊긴 연결에 쓰다 프로세스가 죽는 경로 차단)
- `spawn` 실패 시 `error` 이벤트 미처리로 서버 전체가 죽던 경로 차단
- 화면의 버튼 요청에 `try/catch` — 서버와 연결이 끊겨도 버튼이 잠긴 채 방치되지 않음
- 윈도우에서 "중지" 시 자식 프로세스 트리까지 종료 (`taskkill /T /F`, 실패 시 `kill()`
  폴백) — 남은 크롬 창이 로그인 프로필을 잠그는 것을 방지. **윈도우 미보유로 미검증**

### 검증
- 미실행 상태였던 `전부불러오기`(무한 스크롤 + 답글 펼치기 루프) 최초 실행 — 지연 로딩
  가짜 게시물에서 댓글 32 + 답글 3 전부 수집, 10.9초에 자체 종료, 중복 0
- 수집 댓글 본문에 스크립트·태그가 섞인 경우 미리보기 표·당첨자 카드 모두에서 미실행 확인
- 800명(약 12만 글자) 수집, 중지, 새로고침 유지 회귀 통과
- `전부불러오기` / `인스타게시물주소인가`를 테스트용으로 `module.exports`에 추가

## 2026-09-15 ~ 16 (V1.28 ~ V1.29 전수점검 + 인스타 수집 일원화)

### 버그 수정
- **최근 파일 목록에서 엉뚱한 파일이 열리고 ✕가 다른 캐시를 지우던 문제 수정**
  (기술: 슬롯 버튼이 배열 인덱스(`data-i`)를 참조해, 목록 표시 중 `beforeunload`/
  `visibilitychange`의 `pushSlot`이 `unshift`하면 인덱스가 밀림 → 저장시각+파일명
  복합키(`data-key`)로 조회하도록 변경)
- **참가자가 많은 파일이 통째로 업로드 실패하던 문제 수정 (15만 명 기준)**
  (기술: `computeLengthStats`의 `Math.max(...lengths)` 스프레드가 호출 스택 한도를
  초과 → 단일 루프 최댓값 계산으로 교체, 15만 행 2.9초 처리 확인)
- **서버 응답에 범위 밖 인덱스가 섞이면 후보 화면 전체가 멈추던 문제 수정**
  (기술: `preCandidateRows[m.index]`가 undefined인 항목을 필터링하고,
  `applyCandidates` 진입 시에도 행 없는 후보를 방어적으로 제거)
- **저장 공간 부족으로 목록만 남은 캐시를 눌렀을 때 무반응이던 문제 수정**
  (기술: `applySlot`의 조용한 early return을 제거하고 사유별 안내 메시지 표시)
- **캐시 내용이 손상됐을 때 화면이 죽고 새 파일 업로드까지 실패하던 문제 수정**
  (기술: `loadSlots`가 배열이 아니거나 항목이 객체가 아니면 빈 목록으로 정규화,
  `applySlot`에서 행 단위 형식 검증)
- **지정한 본문 컬럼이 후보 표에서 사라지던 문제 수정**
  (기술: `getMeaningfulColumns`의 10% 임계값에서 사용자 지정 컬럼
  (`contentColumn`/`nicknameColumn`/`postLinkColumn`/`viewCountColumn`)을 예외 처리)
- **당첨 인원수에 소수점 입력 시 한 명 더 뽑히던 문제 수정 (2.7 → 3명)**
  (기술: `drawWinners`의 인원수 계산에 `Math.floor` 적용)

### 인스타 댓글 수집 일원화 (V1.29, 신규 기능)
- **로컬 실행기 추가 — 수집부터 추첨까지 프로그램 하나에서 끝남**
  (기술: `event-raffle/local/`, Node + express + Playwright, `start.bat` 더블클릭 실행)
- **기존 크롬 확장의 댓글 탐색 로직을 이식 (확장 설치 불필요)**
  (기술: 952KB 번들 중 수집 로직 0.9%만 추출해 재작성. 클래스 의존 대신 구조 기반 탐색 —
  "시간표시+프로필링크가 가장 많은 ul"로 댓글 목록 판별)
- **인스타 로그인 1회 후 세션 재사용**
  (기술: 실제 크롬을 전용 프로필로 띄워 수동 로그인 → `storageState` 저장, 자동 로그인 미사용)
- **추첨기 본체 무수정 — 웹 버전 동작 100% 동일**
  (기술: 로컬 서버가 응답 시점에만 `inject-collect-ui.js` 주입, `index.html` 변경 0줄)
- **AI 판단 기능 중계**
  (기술: 로컬 서버가 `/api/plan-filter`·`/api/filter`·`/api/save-result`를 Vercel로 프록시)

### 수집 신뢰성 (V1.29)
- **본문을 못 읽으면 작성자 아이디를 본문으로 기록하지 않고 건너뛰며, 건너뛴 개수를 표시**
  (기술: `본문읽기`가 빈 값 반환 시 행 제외 + `건너뜀` 카운터를 화면·로그에 노출)
- **클래스명이 전부 바뀌어도 본문을 읽어내는 예비 경로 추가**
  (기술: 덩어리에서 `a`/`time`/`button` 제거 후 잔여 텍스트 사용 — 아이디 혼입 불가 구조,
  사용 건수를 별도 집계해 "화면 구조가 바뀐 신호"로 안내)
- **연결 재개 시 같은 수집 결과가 재투입되며 후보 목록이 날아가던 문제 차단**
  (기술: 결과에 `수집id` 부여, 클라이언트가 동일 id면 무시)

### 로컬 실행기 보안·안정성 점검 (V1.29)
- **인스타 로그인 정보가 HTTP로 노출되던 문제 수정 (같은 네트워크에서 접근 가능했음)**
  (기술: `express.static(추첨기폴더)` 제거로 `instagram-session.json` 노출 차단,
  `app.listen(포트, '127.0.0.1')`로 루프백 전용 바인딩)
- **댓글이 많으면 수집 결과를 파싱하지 못하던 문제 수정**
  (기술: 자식 프로세스 stdout이 청크 단위로 도착해 `__RESULT__` 라인이 분할되던 것을
  개행 기준 버퍼링으로 해결. 800행/약 12만 자로 재현·검증)
- **게시물 주소 검증 강화 — 도메인 위장 주소 차단**
  (기술: 문자열 포함 검사 → `new URL()` 파싱 후 hostname 화이트리스트 + 경로 형태 확인.
  로그인 세션이 붙은 브라우저가 외부 사이트로 이동하는 것을 방지)
- **잘못된 요청 본문에 JSON 형식으로 응답**
  (기술: express 기본 HTML 오류 응답을 `{error}` JSON으로 대체)

## 2026-09-07 (V1.24 ~ V1.27 UI 리뉴얼 + 모던 디자인 + 작업 유실 방지)

### 버그 수정
- **캐시가 있는 상태로 페이지를 열면 일부 기능이 조용히 죽어있던 문제 수정**
  (기술: 캐시 자동 복원 호출이 아래쪽 `let` 선언보다 먼저 실행돼 TDZ 오류로 스크립트가
  중단, 이후 이벤트 리스너 등록이 전부 누락되던 것을 복원 블록을 스크립트 끝으로 이동)
- **날짜 컬럼이 46235 같은 숫자로 보이던 문제 수정**
  (기술: `XLSX.read`에 `cellDates: true` 적용 후 `toDisplayDates`로 Date를 표시용
  문자열로 변환, 표·복사·다운로드·localStorage 캐시까지 동일 값 유지)

### 화면 배치 (UI 리뉴얼)
- **후보 표가 화면 높이 안에서 스크롤되도록 변경 — 페이지 59,683px → 2,608px**
  (기술: `.tbl-scroll`에 `max-height:70vh` 적용, 고정 px 대신 뷰포트 기준)
- **600행을 내려가도 컬럼명이 계속 보이게 됨**
  (기술: 스크롤 컨테이너에 높이 제한이 생기면서 `th{position:sticky}`가 실제로 동작,

- **정렬 버튼이 표와 같이 스크롤돼 사라지지 않게 구조 분리**

  (기술: `.wrap` max-width 상향, 줄글은 `.readable`로 760px 유지)

### 조작 편의성
- **행 삭제 버튼을 마우스 올린 줄에서만 표시 — 상시 노출 버튼 623개 → 23개**

  `@media (hover:none)` 터치 기기 예외, 자리 유지로 레이아웃 흔들림 없음)
- **위치마다 제각각이던 삭제 버튼 크기 통일 (23×16/10.5px → 32×24/12px)**
  (기술: `.col-delete` 패딩·폰트 크기를 기존 슬롯 삭제 버튼 기준으로 맞춤)
- **조건을 고치고 다시 필터링하지 않으면 "이전 조건의 결과"임을 화면이 알려줌**
  (기술: `updateStaleNote()`가 `buildCombinedCondition()`과 `lastCombinedCondition`을
  비교해 `#staleNote` 표시, 조건 칸 input/change 이벤트에 연결)

### 작업 유실 방지
- **새로고침해도 필터 결과(후보 명단)가 유지됨 — 이전에는 참가자만 복원되고 전멸**
  (기술: 슬롯 스냅샷에 `candidateRefs`(참가자 인덱스 + 판단근거)만 저장해 용량 최소화,
  `applyCandidates`에서 800ms 디바운스 저장, 구버전 저장본은 `?? []`로 하위호환)
- **행을 지워도 접어둔 줄이 그대로 유지됨**
  (기술: `tableViewState`에 접힘 인덱스·전체접기 상태를 표 바깥에 보관하고 재렌더 시
  복원, 삭제·삽입 시 인덱스 시프트 처리)
- **잘못 지운 후보를 되돌리는 "방금 삭제 취소" 추가**
  (기술: `deletedCandidates` 스택에 삭제 위치와 함께 보관, 원래 자리로 복원)
