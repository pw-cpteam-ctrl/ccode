# 2026-10-19 (V1.5 메일 가져오기가 제자리걸음하지 않도록)

### 메일함에서 가져오기
- 메일이 많아도 누를 때마다 반드시 진전 — 새 메일을 15통씩 끊어 처리하고, 시간이 모자라도 첫 묶음은 끝냄
  (기술: 헤더 247통을 한꺼번에 받던 방식을 UID 목록 검색 + 묶음 가져오기로 변경, 시간 확인은 묶음 사이에서만)
- 이력으로 쓰지 않는 메일(전달 FW, 보낸 사람이 없는 깨진 메일, 읽지 못한 메일)도 '봤음'으로 기록해 다시 읽지 않음
  (기술: `skip` 기록에 폴더·UIDVALIDITY·UID를 남겨 다음 가져오기에서 건너뜀. 화면에는 이력만 전달)
- 결과 안내가 "2026.9.19 이후 메일 247통 중 새 메일 N통을 찾아 이번에 M통을 처리했습니다. 이력에 K통 추가, S통은 제외. (소요 초)"로 상세해짐. 남으면 남은 통수를 알려줌
- 이미 봤는지 찾는 달 파일과 기록하는 달 파일의 기준을 메일함 도착 시각으로 통일 — 메일 머리글 날짜와 도착 날짜가 다르면 같은 메일을 계속 새 메일로 착각하던 문제 방지
- 메일당 가져오는 앞부분을 24KB에서 12KB로 줄임 (인사말은 맨 위에 있고 전송량이 반으로 줄어듦)

# 2026-10-19 (V1.4 연락 이력 — 웍스 메일함에서 바로 가져오기)

### 메일함에서 가져오기
- 연락 이력 탭에서 [지금 가져오기]를 누르면 웍스 메일에서 정해 둔 폴더만 읽어 이력을 정리 — 파일을 올릴 필요가 없음
  (기술: 서버가 IMAP으로 접속, 폴더를 읽기 전용(EXAMINE)으로 열고 BODY.PEEK로 앞부분만 가져옴 — 읽음 표시·이동·삭제 없음)
- 본문은 저장하지 않고 시각·방향·주소·활동명·제목만 비공개 저장소에 쌓음. 새로고침해도 남음
  (기술: `creator-logs/mail-events-YYYY-MM.jsonl`에 한 줄씩 추가, 메일 고유번호(Message-ID) 해시로 중복 방지, 충돌 시 재시도)
- 한글·띄어쓰기가 있는 폴더 이름(예: `Megahouse 협업`)도 읽음. 완성형/분해형 한글, 대소문자 차이도 같은 이름으로 봄
  (기술: IMAP 표준 modified UTF-7로 변환해 보내고, 목록과 비교할 때 NFC 정규화)
- 처음에는 최근 30일, 다음부터는 지난번 끝까지 가져온 시각 하루 전부터 가져옴. [더 오래된 메일(400일)]로 거슬러 올라갈 수 있음
- 가져온 뒤 "2026.9.19 이후 메일 N통을 확인해 M통을 새로 가져왔습니다"처럼 어느 날짜부터 몇 통을 봤는지 알려줌 — 0통이 '기간에 메일이 없어서'인지 알 수 있게 하려고(연도까지 적어 작년 날짜가 지난달로 읽히지 않게 함)
- 한 번에 최대 120통·약 7.5초 — 더 남으면 "한 번 더 눌러 주세요"라고 안내 (서버 함수 시간 제한 때문)
- [폴더 확인]으로 설정한 폴더를 찾았는지 확인. 이름이 틀리면 오류 대신 실제 폴더 목록을 보여줌
- 비밀번호 오류 / 서버 연결 불가 / 설정 없음을 각각 알아볼 수 있는 안내로 표시
- 기존 파일 올리기는 예비로 남기고, 메일함 이력과 합쳐서 같은 화면에 정리
- 파일로만 볼 때는 오래된 파일 경고를 유지하되, 메일함에서 가져온 경우에는 경고하지 않음(새 메일이 없어서 오래돼 보일 수 있으므로 '마지막으로 가져온 시각'을 보여줌)

### 화면
- 폰에서 버튼이 한 줄에 안 들어갈 때 줄을 바꿔 페이지가 옆으로 넘치지 않게 함

# 2026-10-19 (V1.3 연락 이력 — 메일 파일 읽기)

### 연락 이력 (새 탭)
- 일간 메일 추출 파일(.md)을 올리거나 붙여넣으면 크리에이터별로 정리 — 답 대기 며칠째, 마지막 연락 날짜·방향, 최근 메일 제목 3개
- 내가 마지막으로 보냈으면 "N일째 기다리는 중", 상대가 마지막이면 "내가 답할 차례 N일째" — 후자를 먼저 보여줌
- 메일 내용은 이 브라우저에서만 읽고 서버로 보내지도 저장하지도 않음 (새로고침하면 사라짐), AI는 쓰지 않음
  (기술: 파일을 브라우저에서 정규식으로 파싱. 한 통에 인용된 대화 전체로 이력 복원, `FW:` 최신 메일은 제외, 같은 메시지는 분 단위 시각+방향+상대로 중복 제거)
- 활동명은 보낸 메일의 "안녕하세요, ○○님"과 받은 메일의 "○○입니다"에서 읽음. 발신자 표시 이름은 활동명과 달라 쓰지 않음
  (기술: 주소와 활동명을 둘 다 가진 메시지에 표를 던져 주소↔활동명을 짝지음)
- 확정 후보 표의 '연락 이력' 칸도 같은 결과로 채워짐 (후보 활동명과 같으면 표시, 없으면 "메일에서 못 찾음")
- 파일 안의 가장 최근 메일 시각을 표시하고, 하루 넘게 지난 파일이면 경고 — 오래된 파일은 이미 답한 건까지 "내가 답할 차례"로 보여 틀린 정보가 되기 때문

### 화면
- 탭이 5개로 늘어 폰에서 옆으로 밀 수 있고, 지금 보는 탭이 보이도록 자동으로 맞춤
- 접수 목록 표용 "칸 폭 1px" 규칙을 접수 목록 표에만 걸리게 바로잡음 — 새 표를 만들 때마다 폰에서 칸이 눌리던 원인 제거

# 2026-10-19 (V1.2 저장소를 못 읽을 때 빈 화면 대신 이유 표시)

### 접속
- 접속 코드는 맞는데 접수 기록 저장소를 못 읽을 때, 빈 목록 대신 이유를 안내 — 키가 거부됨 / 저장소 권한 부족·저장소를 못 찾음
  (기술: 목록을 읽기 전에 GitHub 저장소 상태를 먼저 확인(`repoStatus`), 401→`token`, 403→`perm`, 그 외→`repo`로 응답)
- 이런 오류에서는 기억해 둔 접속 코드를 지우지 않음 — 저장소가 다시 읽히면 코드 재입력 없이 바로 열림
  (기술: GitHub은 파일이 없을 때와 키가 저장소를 못 볼 때 둘 다 404를 줘서, 기존에는 권한 문제가 '기록 없음'으로 보였음)

# 2026-10-14 (V1.0 담당자 화면 분리와 응대 기능)

### 분리
- 크리에이터 가이드 안에 있던 담당자(관리자) 화면을 별도 도구로 분리
  (기술: `reward-view-admin.html` + `api/admin.js` + `lib/github.js`를 복사해 독립 Vercel 프로젝트로 구성, 데이터는 기존과 같은 비공개 저장소 `creator-logs/*`를 그대로 읽고 씀)
- 기존 기능은 그대로 — 접수 목록, 업로드 확인, 리워드 지급 표시, 수령 방식 변경, 오픈 날짜 관리
- 배포되는 파일은 화면 파일과 robots.txt뿐 — 계획서 같은 내부 문서는 주소로 열리지 않음
  (기술: `vercel.json`의 buildCommand가 `dist/`에 두 파일만 복사)

### 회차 현황 (새 입력 없음)
- 회차별 주간 할 일 표 — 초안·업로드 확인·1차 지급·정산이 몇 건인지 주마다 표시
- 두 회차 이상의 일이 같은 주에 몰리면 "겹침"으로 표시, 날짜가 지났는데 안 끝난 일은 "밀린 일"에 모음
- 크리에이터별 현재 단계와 다음 날짜 표시
  (기술: 초안일·오픈일·업로드 확인·지급 표시만으로 계산, 오픈일은 가장 가까운 오픈일 기준)

### 쿠폰 발급
- 지급할 차례가 된 건의 네이버 ID·차수·금액(또는 상품)·지급 예정일을 한 표로 표시
- 표 복사와 CSV 내려받기, 발급 후 지급 표시 버튼 (접수 목록과 같은 값이라 양쪽에 반영)
- 2차(750↑ 여부)와 후지급(정산 결과) 금액은 "확인 필요"만 표시, CSV에는 조건 설명 없이 값만 포함
- 크리에이터가 쓴 글이 엑셀에서 수식으로 실행되지 않도록 방어
  (기술: `=`, `+`, `-`, `@`로 시작하는 칸 앞에 `'` 부착 — CSV 수식 주입 방어)
- 좁은 화면(폰)에서는 건마다 카드로 표시

### 확정 후보
- 노션에서 최종 확정된 분의 표를 복사해 붙여넣으면 활동명·링크를 읽어 목록에 추가
- 접수 목록과 활동명이 같으면 자동으로 이어져 "접수 전 / 접수됨 · 현재 단계" 표시
- 연락 이력 칸은 자리만 있음 (메일 추출 파일 반영 예정)
  (기술: 비공개 저장소 `creator-logs/candidates.json` 신규 파일, 기존 파일은 변경 없음 — 없으면 빈 목록으로 처리)
